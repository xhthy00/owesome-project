## 一、判定规则（四层证据，缺一不可）

1. **回答层**：回答中是否出现超出范围的学生、班级、学校、区县名称或数值。
2. **SQL 层**：审计 `tool_call_log` / 会话事件里的语义 SQL 是否带范围条件。物理 SQL 与连接信息不得下发给用户。
3. **结果层**：表格行数、列名、图表标签、导出文件（PDF/Word/Excel）是否与回答一致。
4. **错误层**：拒绝时是否有稳定错误码与 `category`；技术故障不得写成“没有权限”。

> 注意：**单纯返回空结果不算通过**。只有 SQL 确实带上范围条件、或明确拒绝并给出原因，才算通过；SQL 无范围条件却因数据缺失恰好为空，按“不通过”记录。
> 允许“收窄后返回本校/本班数据”，也允许“直接拒绝”；同一用例两种结果都算通过，但必须在记录里写清实际是哪一种。

## 五、当前实现的重点观察项

1. **全市班级排名对照池（RANK + `GROUP BY xx/bj`）会放开本校谓词。**
   代码证据：`query_permission.py::_sql_is_citywide_rank_pool` → `merge_row_predicates_into_sql(skip_school_scope=True)`；`tests/agent/test_row_perm_rank.py` 也断言该形态下不注入学校条件。
   但 `docs/education_permission.md` 写的是“`GROUP BY xx` 各校排名仍注入本校”。用 C4/E10 验证：若结果出现他校 `xx`/`bj`/均分，按产品口径确认是否只应返回位次；若不应暴露他校名单，记为缺陷。

2. **学生角色问全市/区县聚合时，学生谓词会被“全市指标”判定剥离。**
   `_is_citywide_metric_select` 只拦学校粒度，不拦 `student_id`；实测 `SELECT AVG(score) … FROM tb_score` 加学生谓词后条件被丢弃。与文档“学生角色不开放全市”不一致，用 C7 验证。

3. **`tb_score_detail` 依赖 `EXISTS` 关联 `tb_score` 才能挂学校/班级条件**；只查明细表且无 `sc` 关联时，条件可能挂不上。用 E5 验证。

4. **`tb_score_indicator` 的学校条件是 `school_name LIKE`，学生角色直接 `1 = 0`**；指标表与明细表口径不同，E6 专门覆盖。

5. **v2 下平台管理员不再默认豁免**，业务查询必须有业务授权；G10 专门覆盖。

6. **技术故障与权限拒绝必须可区分**：`service_unavailable` 不得显示“无权限”，也不得弹“重新授权”让用户反复重试（F6）。

## 六、附：非提问类权限检查（管理面，建议同批执行）

- 普通成员访问“权限管理 → 教育权限”应不可见或 403。
- 受限管理员不能给他人授予超出自己范围/能力/有效期的授权。
- CSV 批量导入含一行越界范围时，整批原子失败，不部分写入。
- 撤权后 `managed_resources` 标记仍保留，防止回退旧权限。
- 修改范围/能力后，旧会话与旧报告按新指纹重新鉴权。
- 审计表能看到授权变更、拒绝原因、工具调用 SQL；日志中不出现物理连接串。

## 七、扩展提问的生成公式

按维度组合即可批量派生新用例：

```text
【账号】市局 / 校长 / 教师 / 学生 / 空授权 / 他校校长
【范围】本校 / 他校（脱敏码）/ 本班 / 他班 / 全区县 / 全市
【对象】某年级 + 某学科 / 全科
【时间】高三3月 / 高三5月模拟 / 高二期末 / 近N次
【粒度】聚合值 / 分组（区县、学校、班级）/ 学生名单 / 单人画像
【意图】总览 / 对比 / 诊断 / 趋势 / 预警 / 导出
【绕过话术】换表名、加引号、WITH、UNION、子查询、RANK、去过滤、要底层 SQL
```

最小覆盖集：每个账号至少覆盖「本校正向 1 条 + 他校明细 1 条 + 全市聚合 1 条 + 排名 1 条」，再对校长与教师各补 2 条 SQL 形态绕过。

# 提问链路代码审计与整改

日期：2026-11-09。

范围覆盖所有现用提问入口：`chat-stream`、`generate-sql`、`execute-sql`、CLI 冒烟与教育评测入口，React 和保留的 Vue 客户端，以及共用的模型封装、消息转换、DeepAgents middleware、checkpoint、DataSemantic、权限执行、SQL 驱动和记录持久化。回归还覆盖仓库已跟踪的后端测试文件。

## 已修复的共用机制

| 隐患 | 修复后的行为 |
| --- | --- |
| 规划和其他工具同批返回时，整批被丢弃 | 保留有效 `write_todos`；同批后续操作得到未执行提示，等待计划落地后再提交。 |
| 计划仍有 pending 阶段，却提前输出完成结论 | 有界提醒执行剩余阶段；仍未推进时明确标记分析未完成，并回收草稿。 |
| 强制具名规划工具挡住必要的追问 | 交互式规划阶段同时开放规划与追问，使用 auto，由宿主门禁验证执行顺序；无追问工具的入口继续使用原网关兼容选择。 |
| 修复提示作为历史 system 消息残留到下一问 | 临时指令带生命周期标记，新一轮删除；兼容清理旧版同类修复指令。 |
| 推理模型的工具续轮丢失 reasoning_content | 流式、非流式均保留推理字段；仅向支持该字段的原生网关回传，不混入用户答案。 |
| 当前 MiniMax-M3.1-Flash 未匹配容量表 | 原生端点补齐 1M 容量，SDK profile 优先；未知端点继续显示容量未知。 |
| 输出被截断后仍按规划失败重复重试 | 识别 `finish_reason=length`，报告输出长度上限，不在相同限制下空转。 |
| 查询过候选数据后无法再澄清 | 允许查询后调用 `ask_human`；同批其他操作延后到用户回复后。 |
| 同批多个追问产生多个 interrupt，但界面只保存一个 | 每批只等待首个追问，其余返回未执行结果，避免合法回复被判失效。 |
| 追问和规划同批返回，追问又被规划门禁挡住 | 追问优先于同批规划及业务操作；等待回复后重新提交计划或查询。阶段推进时仍保持追问可用。 |
| 普通新消息被默认为旧追问的答案 | 恢复必须提供匹配的 interrupt ID；缺少 ID 时重新展示原追问，明确换题则结束旧等待。 |
| 追问只有单段文本，无法表达多项确认 | 对照 my-cowork 提供单选、多选、文本字段，支持必填、跳过选填和自定义回答；提交后恢复原任务。 |
| 简单问题跳过条件评估，发现多个候选后直接扩展范围 | 所有业务问数先接受独立结构化评估；条件足够才放行，必要时只读探查并重评估或原生追问，评估失败不默认放行。 |
| 刷新重新弹出已答/已结束的旧追问，失败后丢失待回复卡片 | 保存回复关联与取消标识，兼容旧历史；前端按生命周期恢复，发送时保留草稿。图确认事件独立于展示记录保存。 |
| 目录临时故障导致客户端清掉尚有效的追问 ID | 未触碰图状态的失败显式保留 ID，重试可以继续恢复原任务。 |
| query 和 chart 同批执行时读取旧结果 | 绘图等待该批查询返回后再执行。 |
| 异常、停止或预算结束后删除整条会话 | 使用公开图状态更新恢复稳定 checkpoint、闭合未配对工具消息、清理待执行任务；保留之前成功的历史和归档。 |
| 失败工具仍显示 running，部分查询失败却显示全部完成 | 收束未结束的工具/步骤；成功修复后清除旧错误，仍有未解决查询失败时标记未完成并说明覆盖范围。 |
| 问候和显式指标定义被统一判为“没有查询结果” | 允许明确的通用问候、指标定义直接回答；具体学校、考试、人数等业务问题仍须本轮数据证据。 |
| 空白问题及无效 ID 进入模型链路 | 请求校验提前拒绝；保留原有用户、工作空间、数据源和发布版本边界。 |
| SQL 解析失败默认放行；只检查顶层语句 | 只接受单条只读查询，拒绝写入 CTE、SELECT INTO、锁和多语句；解析失败即拒绝。 |
| 连接 timeout 被误认为 SQL 执行 timeout | 问数使用只读数据库事务；PostgreSQL statement_timeout、MySQL MAX_EXECUTION_TIME/read_timeout，默认单条 60 秒，可配置。 |
| NaN/Infinity 让浏览器无法解析事件 JSON | 转换非有限数值为 null，并递归处理数组、对象中的值。 |
| SSE 提前 EOF 被当作完成；异步落库同步回调未等待 | 必须收到终止事件；等待异步完成处理；中断时不把部分结果标成完整成功。 |
| 中止旧请求后，排队事件覆盖新会话 | 取消信号及 active run 检查阻止旧事件和旧异步同步回写。 |
| Vue fetch 绕过 axios，缺少登录令牌及新事件契约 | 补齐鉴权、恢复 ID、规划/推理/正文/澄清事件；同样校验终止事件和分片边界。 |
| Vue 响应式展开与 ChatRecord 的私有实例方法类型冲突 | 无状态报告提取器改为私有静态方法，保留封装并使 Vue 类型检查通过。 |
| CLI 传递已删除参数；错误摘要被算为成功 | 采用明确的模型调用上限参数；错误事件和失败终态影响退出码。 |
| 通用 LLM 封装把 assistant/tool 消息改成 human | 使用 SDK 消息转换保留角色、工具调用和结果配对；历史解析不再添加空消息。 |
| 结构化提示未实际写回 BaseMessage，或修改调用方原始字典 | 通过拷贝后的消息应用格式要求，保留原始历史不变。 |
| Ollama 已带 /v1 的地址被追加成 /v1/v1 | 规范化版本路径，支持两种常用地址形式。 |
| 记录保存失败静默返回 0 | 保留已返回结果，同时显示保存失败步骤，便于发现持久化异常。 |
| 同步范围探查阻塞流式 API 的事件循环 | 将独立范围探查移入工作线程。 |

## 验证

- 提问链路专项：197 项通过，包括共用条件评估、简单问题探查/澄清/恢复、规划、并行批次、跨网关追问、归档、预算、模型封装、SQL 执行保护、SSE 心跳、兼容入口和用量统计。
- 前端全量：59 项通过，包含表单、追问生命周期、刷新恢复、React 与 Vue SSE 解析兼容检查。
- Vue：`vue-tsc --noEmit` 通过。
- 修改文件 Ruff 与 `git diff --check` 通过。
- React 类型检查仍有两项已在原始 HEAD 复现的既有问题：缺少已声明的 `docx-preview` 安装依赖，以及 `education.ts` 的 PaperOutline 类型转换。

前一轮完整后端回归与原始 HEAD 在同一依赖、同一隔离数据库配置下比较；测试连接指向不可写的隔离目标，避免旧测试触碰业务库。机器可读的历史结果和逐项失败原因保存在 [全量基线对照](../artifacts/chat-runtime-audit/full-suite-comparison.json)。本轮独立评估新增专项并完成上述197项回归，未将前一轮全量比较当作本轮重新运行的结果。

## 仍未全绿的既有测试

前一轮基线比较中，修改前后共有相同的55项失败，没有新增失败。它们不能被当作本次修复已解决的功能，也不能仅凭测试失败直接认定线上业务错误：

| 既有失败分组 | 数量 |

| 教育 API（鉴权、配置和依赖隔离） | 6 |
| 旧教育工具统计、模板 | 5 |
| 旧报表编排 | 3 |
| 旧报表类型及模板显示 | 3 |
| 试卷题目解析 | 2 |
| 教育权限 API | 2 |
| 旧摘要、教育统计回归、cohort、KPI SQL、科目模板、workspace 测试 | 6 |

这些项目需要结合各自现行业务口径和测试夹具继续核对；未通过修改期望值或删除测试来把全量结果变绿。

本次自动化覆盖共用机制和确定性故障场景，不构成对任意自然语言输入、任意外部模型/数据库故障都成功的证明。缺少数据、权限或发布口径时，应明确说明范围或澄清，不能用虚构结果换取“成功”。

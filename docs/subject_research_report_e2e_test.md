## 待修 R1：历史小题"单选11"被错误入选（唯一的小题残留）

HTML 入选集 {1,2,4,5,6,8,**11**,12,13,14}，Word 为 {1,2,4,5,6,8,12,13,14}——多了单选11。

**根因定位**（连库复算）：按「排除市报 + RANK(原始均分)」扬中题11 排名第 3，总分排名第 1，差值 +2 < N=3，**不应入选**。库内逐题复核还证实：该规则下的入选集与 Word 转置表 9 题**逐一吻合**。

为什么系统算成了 ≥3？嫌疑在 `_lagging_from_school_avgs` 的分母分支：

- `score_school_avg_select_sql`（供 unit_n/在籍人数）带 `ov.xsxz='在籍生'` 过滤；
- `item_school_select_sql`（明细 COUNT(*) / AVG）**不做在籍过滤**，且 `LEFT JOIN tb_exam_question` 在同一 question_no 多个 exam_id 行时会使每条 sd 连接出多行 → cell["n"] 虚增；
- 于是部分学校触发 `else` 分支走"明细行数分母"，缺考未补 0 → 均分虚高 → 把扬中挤到第 4 名以后。

实测证据：历史题11 按行数分母有多校并列满分 3.00（真实全员均分只有 0.2~0.4）。修复方向：小题 SQL 补上同样的在籍过滤 + 防止 eq join 行膨胀（按 question_no 去重或取 MAX），保证两套 n 同口径。

## 待修 R2：语文临界生贡献分阈值仍偏高（铁证级反例）

物理方向 211 线：Word 20 人 / 系统 23 人。差集显示 **Word 的 19 个分数对全部包含在系统名单中**，系统多出的 3 人为：

```
(总分555, 语文115)、(总分555, 语文114)、(总分554, 语文114)
```

这 3 人的学科分比 Word 入选者的最高分还高（多数 ≤113）。若他们满足"< 贡献分"，则系统贡献分 >114；而 Word 不收录他们 → **Word 的语文贡献分落在 (113, 114]**。这是可直接用于校准的反例。

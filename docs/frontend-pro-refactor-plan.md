# 学情分析智能体前端重构开发落地方案

## 1. 目标与设计依据

以 `prototype/web` 为全站视觉验收基准，以现有 `frontend-react` 为业务行为验收基准。新前端以 Ant Design Pro、Umi Max 和 Ant Design 6 搭建工作台，Ant Design X 用于问数交互，Ant Design Charts 用于总览及逐步迁移的业务图表。

- **工作台**沿用原型的品牌、全宽顶栏、可折叠侧栏、蓝白主题、浅蓝背景纹理和分析页布局。指标、筛选、排名、报告历史和后台表格接入实际接口。原型中的演示数据、固定排名和模拟权限均不进入生产实现。
- **AI 问数**以 `frontend-react/src/components/chat/CoworkChat.tsx`、`frontend-react/styles/cowork-chat.css` 为布局和样式依据。保留欢迎态、消息与结果卡、会话标题栏和底部输入区的位置与尺寸关系。Ant Design X 作为这一结构内的组件底座。
- **业务边界**覆盖现有 React 应用的用户可达功能。原型没画出的导入、数据权限、配置、历史会话、分享和移动入口先做路由与功能盘点，按现网能力验收。此次迁移沿用后端接口、登录协议、工作空间隔离和权限判定。

## 2. 技术与目录决策

| 层级 | 落地做法 |
| --- | --- |
| 应用框架 | 以官方 Pro 目录结构建立独立生产工程，建议放在 `frontend-pro/`。使用 Umi Max 路由、运行时 `layout`、ProLayout 和 PageContainer。按实际页面模块拆分路由，原型中通过 pathname 手工选择页面的做法留在原型。 |
| 依赖基线 | 原型 lockfile 已验证的组合为 Umi Max 4.7.34、Pro Components 3.1.14-7、Ant Design 6.7.1、React 19.3.1、Ant Design X 2.10.0、Ant Design Charts 2.6.7。首个开发批次以这些版本做兼容验证并提交锁文件，Node 构建环境对齐原型的 22.x。核对 Umi 布局插件实际加载的 Pro Components 版本。 |
| 样式 | 全站通过 ConfigProvider 和 ProLayout token 管理主色、圆角、间距与背景。沿用问数专属布局样式，限定在问数工作区，隔离 Tailwind reset、全局选择器和 Ant Design v5 内部类迁移。 |
| 展示组件 | 新管理页优先使用 ProTable、ProForm、PageContainer；复杂导入保持原多步流程与错误反馈。新图表统一使用 Ant Design Charts，已有问数图表先复用 `AnswerVisual` 与渲染适配，等图表规格、筛选及导出回归达标后替换。 |
| 业务复用 | 先移植 `src/api`、`src/auth/session.ts`、问数状态与导出模块，再在边界处适配 Umi 导航与新版组件。报表预览、导出和图表包按路由或使用场景懒加载。 |

## 3. 页面与旧入口映射

| 原型模块 | 正式实现和兼容入口 |
| --- | --- |
| 学情总览 | 以 `/` 承载，整合有真实口径的考试覆盖、达线、优秀率及异常；原探索广场下线，`/overview` 重定向到 `/` 兼容旧链接。考试批次、学校作为图表和排名的同一查询范围，指标单位和空态随口径显示。 |
| AI 问数 | 保留 `/chat`、`/chat?conversation_id=...`、`/chat?q=...&ds=...`。迁移 `/conversations`、`/mobile/chat`、`/share/:token` 时验证现网实际行为。分享和移动入口保留原路径及各自的鉴权规则。 |
| 学情分析 | 将 `/construct/analysis` 与历史页映射到原型的报告生成、历史及预览结构，保留独立历史深链接、任务状态和导出能力。 |
| 达线看板与异常提醒 | 复用 `/construct/education/line-reach`、`anomaly-alerts`、`anomaly-rules` 对应业务，保留告警详情入口及规则维护。 |
| 数据与权限 | 按原型组织数据库、学校、试卷、成绩等业务导航和资源列表；保留导入页、试卷详情及角色、成员、工作空间、资源、教育细粒度权限和隐私配置。 |
| 系统日志和辅助模块 | 将操作、登录、访问日志组织为统一页面入口，保留 `/system/log/*` 深链接和导出。文档、知识库、技能、模型及提示词等非原型页面按盘点结果逐个迁移。 |

**URL 策略**建议正式版本使用浏览器路由。原有业务入口直接匹配正式路由或重定向到等价页面并保留查询参数。原型继续使用 hash 路由。刷新、前进后退、登录后返回、旧收藏链接和分享链接都列入验收。

## 4. 问数迁移与保留要求

### 保留现有布局

- 桌面左侧使用工作台侧栏承载「新建任务」「最近任务」。欢迎态保留头像与问候横排、居中输入框与两列推荐问题。
- 会话中部保留标题、状态和操作区，消息独立滚动，输入框固定在会话列底部。已向上阅读历史时，流式更新保留当前位置，并提供回到底部入口。
- 桌面右栏默认展示任务进度，可折叠为可重新展开的窄轨道。打开结果后由预览替换进度区，关闭结果后回到此前的进度状态。窄屏使用抽屉。保留原问数的报告、图表、数据表和可用的 SQL 入口，展示内容按后端权限与响应决定。
- 首批保留现有消息、报告和澄清表单的结构。逐项引入 Ant Design X 的 Sender、Conversations、Bubble，核对键盘交互、输入高度、头像、富文本、表格及结果卡的位置。Sender 继续保留原数据源选择、停止操作和使用量入口。生成中的输入框使用移植自 BoardUI 的 Composer Loader：4 色渐变光带沿输入框边缘绕圈，清晰线 + 紧辉光 + 向内 bloom 三层叠加，每圈 4.5 秒、弧长 120°，淡入淡出 450ms；上方状态使用同源的 Agent Thinking（infinity 彗星 + 流光文字 + 已工作计时）。两者只在当前会话生成中显示，并遵循系统的减少动态效果设置。

### 复用会话业务链路

1. 从 `pages/chat/index.tsx` 迁移路由接入，保留 `q/ds` 只消费一次、历史会话恢复以及新建任务清理的逻辑。UI 事件通过现有 `useChat` 发起。
2. 复用 `src/hooks/useChat.ts`、`src/api/adapter/chatAdapter.ts` 和现有 SSE 工具。保持 `conversation_id`、`datasource_id`、`resume_interrupt_id` 及运行、记录、报告之间的关联。进度从实际事件更新。
3. 用真实流式接口验证正常完成、手动停止、网络异常、切换会话、再次提问及追问恢复。保留流式中同一会话的加载保护，避免历史响应覆盖当前生成。校验超时或旧响应返回时，界面与当前会话仍一致。

## 5. 开发顺序与验收关口

| 阶段 | 开发任务 | 完成条件 |
| --- | --- | --- |
| P0 基线与盘点 | 固化最新版原型和当前问数页截图、录制关键流程。按旧路由记录入口、权限、接口、部署依赖和迁移去向，确认总览真实指标口径。 | 设计可逐屏对照。旧入口均有迁移方案、灰度保留方案或明确的产品下线决定。 |
| P1 框架与会话 | 建立 Umi Max 工程，接入 Pro 工作台、主题、资源、登录、工作空间和权限菜单。完成同源 API 代理及 SSE 冒烟，建立生产构建和浏览器检查。 | 登录、退出、工作空间切换、非授权访问和深链接已验证。代理中能观察到逐帧 SSE 输出。 |
| P2 问数纵切 | 迁移真实问数链路和原布局。按 `useChat` → 页面路由 → 欢迎、消息、任务及预览区 → Ant Design X 组件接入的顺序交付。 | 用同一套测试问题核对新旧会话结果与布局。新建、历史、追问、停止、导出和权限路径通过。 |
| P3 学情与后台 | 先上线总览、分析报告、达线和异常，再逐批替换数据、权限、审计和辅助模块。每批接真实服务，覆盖资源列表、表单、批量操作、导入与导出。 | 过滤、分页、表单校验、失败重试和权限行为与现网规则一致。没有默认以静态样例代替接口的页面。 |
| P4 灰度与切换 | 新旧构建并行部署，按工作空间或受控入口开放新版，跟踪流式体验、关键页面错误和操作成功率。 | 流程验收通过，能演练网关回切，并能从旧页面打开灰度期间建立的会话、报告和记录。 |

建议以阶段为交付边界。校内或区域教研试用时优先验证 P2，后台模块可以并行开发。任一批次发现实体标识、权限语义或导出行为变化，先补齐迁移验证再扩大范围。

## 6. 验收清单

- **视觉**以当前原型核对总览和后台。问数以原 React 页面截图核对桌面 1440px、常用笔记本宽度及 375px 窄屏，覆盖欢迎、运行、追问、完成、预览、侧栏折叠和长标题。确认底部输入框始终可达，滚动区域不互相抢占，可用键盘完成提问与结果切换。
- **会话**移植现有 `useChat`、`chatAdapter`、`CoworkChat`、`AnswerVisual`、`HumanQuestionForm` 测试，补真实 API 或录制 SSE 的浏览器回归。覆盖恢复历史时不重复发起问数、停止后不再插入旧内容、同一会话追问恢复，以及切换工作空间后不泄漏上一个空间的记录。
- **业务**核对各页真实接口的数据、筛选、排序、导入确认和报告导出。用具备不同权限的账号验证同一路由下的数据范围，直接访问无权页面时后端也拒绝请求。
- **工程**每批合入前执行锁文件安装、类型检查、单测和生产构建。通过代理跑浏览器回归，记录首包体积、首条流事件时间及关键接口错误率，以旧版实测作为灰度比较基线。

## 7. 部署、灰度与回滚

当前 `deploy/Dockerfile` 打包 Next.js，`deploy/nginx.conf` 将页面及 `/api/` 指向 Next，`frontend-react/next.config.js` 再将 `/api/:path*` 改写至后端。新版本按静态构建发布时，单独配置页面回退到入口 HTML 与静态资源路径，`/api/` 保持同源并等价转发到后端。先验证路径前缀改写与代理头再承接流量。

- SSE 路径保持禁用代理缓冲、缓存及响应压缩，设置与当前线上行为兼容的超时。用部署环境确认第一段内容能在流结束前到达浏览器，停止请求可以及时断开。后端 `chat-stream` 已带 `Cache-Control: no-cache, no-transform` 与 `X-Accel-Buffering: no`：Umi 开发服务器（`@umijs/bundler-utoopack` 的 `compression()`）会对 `text/event-stream` 做 gzip，一旦压缩就会攒包，表现为"跑完才一次性出结果"；`no-transform` 让压缩中间件直接跳过。若网关启用 gzip，务必把 `text/event-stream` 排除，或整段关闭压缩。
- 首次灰度使用独立构建产物和可切回的流量入口。两端使用同一套后端、会话与权限，避免在迁移期引入只适用于新版的持久化格式。保留旧版构建与网关规则，记录回切命令和验证路径。
- 做环境配置、静态资源前缀、技能市场配置、登录与工作空间存储兼容检查，确保灰度切换或回切后可无损访问历史数据。

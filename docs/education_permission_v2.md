# 模型显式权限 SQL：实现与启用

本实现不创建授权表，不修改 DataSemantic 服务。范围与能力保存在现有 `sys_user.system_variables.edu_auth_v2`。权限页面固定针对 `DATABASE_EDU_URL` 的学情业务库，不提供数据源选择；模型必须生成权限条件，宿主不会补写 WHERE。

## 统一查询契约与版本

`src/datasource/service/semantic_permission_contract.py`是模型、校验器和失败恢复的共同规则入口。当前契约为`education-sql/1`，证明器为`relational-proof/2`。它从审核后的RelationPolicy生成类型化契约，统一定义能力对应的参考池范围、参评单位、指标/样本、精度与门槛、允许的分组、SQL结构、展开上限和修正次数。指标定义在策略加载时检查，不能包含未发布字段、子查询、窗口或多个SQL表达式。

模型收到`query_contract`标识和同源的`reference_query_contract`，校验器直接消费这些规则。规则中的指标标识不是数据库字段；误用时返回对应表达式供模型修正。宿主不生成SQL、注入WHERE或替模型执行修正。

逻辑证明绑定当前授权指纹和查询契约指纹，编译后必须在相同契约下重新证明每条数据路径。契约、证明器、发布物、授权或强制旧规则变化时，旧证明不能沿用。结果附带契约版本、证明器版本和指纹；上下文及旧结果的鉴权指纹也包含契约身份。变更校验规则必须更新契约/证明器版本并通过编译形态和越权变体矩阵。

升级会使旧会话/旧结果的上下文失效，需要重新发起查询；原账号授权和授权revision不因此变化。连接迁移仍沿用固定逻辑资源`education`。

```mermaid
flowchart LR
  P[审核映射与授权] --> C[统一版本化契约]
  C --> M[模型生成完整语义SQL]
  C --> L[逻辑权限证明]
  M --> L
  L --> D[DataSemantic编译]
  D --> V[按同一契约验证物理数据流]
  V --> E[只读执行与执行后重验]
  L --> R[宿主分类与有界恢复]
  V --> R
```

## 失败恢复责任

错误保留原code，并统一返回`category / failure_stage / recovery_action / retryable / user_message / requires_user_input`。分类由宿主决定，调用者不能把不可修复错误标记为可重试。

| 分类 | 示例 | 宿主行为 |
| --- | --- | --- |
| access_denied | 无有效授权、账号停用、禁止字段 | 停止；不让模型建议自行放宽授权 |
| query_invalid | 范围条件不完整、未批准指标/输出、错误字段引用 | 模型按契约修正SQL，最多两次 |
| query_unsupported | 相关/标量子查询等当前证明器不支持的结构 | 明确说明不支持，可改成已支持结构，最多两次 |
| compiled_plan_unverifiable | 编译结果范围、来源、释放路径或输出证明不一致 | 立即停止并交管理员诊断，不能让模型绕过 |
| policy_invalid / context_changed | 映射异常、契约/发布版本变化 | 停止，修复配置或重新加载上下文 |
| service_unavailable / execution_failed | 规划服务不可用、已验证SQL执行失败 | 保持技术故障归因，不说用户没权限，不反复改SQL |

第一次技术失败起就不能调用ask_human弹出“是否继续/是否重授权”。v2数据查询按轮次串行进入恢复门，排队调用在执行前再次检查停止状态，避免并行工具突破最多两次修正的上限。成功恢复后可继续正常业务澄清；已终止的轮次不能被后续成功回调重开。

最终失败说明由宿主生成，不采用模型猜测的“权限未开通”等解释。失败只代表对应查询失败，不能抹去之前成功返回的数据。

当后续查询被拒且已有成功结果时，宿主先按当前授权指纹重新筛选结果，再在原有模型/Token预算内最多调用一次独立的答复整理器。整理器只收到原问题、确认条件与成功结果，只能提交答复、引用结果ID及complete/partial覆盖程度，不能再查询数据。它不接收失败SQL和错误归因；这些由宿主单独说明。整体对比已覆盖问题时不需要各校明细或排名。

整理前后均重新核验授权，授权变化时不再发布旧结果。无有效引用、结果截断、模型预算耗尽、整理超时或格式无效时，保留成功结果表格，不退回只有错误文字的答复。成功覆盖原问题时按主任务成功保存，额外拒绝继续保留在tool_calls审计中；只覆盖部分时明确缺口。最终答复同步回会话检查点，避免后续续问沿用被替换的错误解释。

## 执行链路

1. 宿主加载真实用户、空间成员关系、有效授权和审核发布映射；平台管理员使用业务查询时也需要业务授权。
2. 向模型提供逻辑权限键、审核指标、有效期/历史区间、样本与单位数门槛和旧强制行规则。
3. 模型通过现有 `query_semantic` 提交完整 SQL，包括普通过滤或参照池及最终自身过滤。
4. 语义 AST 校验通过后才调用 DataSemantic `/plan`；宿主再验证物理来源、过滤、参照池数据流和输出契约。
5. 最终 AST 再次验证，只读执行，自动 SQL 修正次数为零；执行前后重新加载权限，变化或到期时丢弃结果。
6. 模型和普通 SSE/历史只得到语义 SQL 与授权结果，不得到编译物理 SQL；旧结果与报告读取按当前指纹重新鉴权。

可修正权限错误包含 `error_detail.code / retryable / source_alias`。同一轮最多两次权限修正；失效或物理证明失败终止后续业务查询，不能通过改变写法绕过。

## 固定学情库与页面配置

使用已有 `DATABASE_EDU_URL` 和唯一的 `DATASEMANTIC_BINDINGS` 发布绑定即可，无需新建数据源记录或另配 `SEMANTIC_PERMISSION_MANIFEST_PATH` 文件。后者仅保留为兼容高级自定义策略的入口。

后端直接从学情库读取 `tb_score_overview` 的组织元数据：`dq` 为区县、`xx` 为学校、`jc` 为届次、`bj` 为班级。页面选项使用实际存储值，不猜学校名称、年级前缀或届次。相同班名仍需同时匹配学校和届次。

城市范围绑定固定的逻辑资源 `education`，页面显示“全市”，SQL 不要求添加数据库中不存在的 city_id 列。修改 `DATABASE_EDU_URL` 的主机、端口、数据库名、用户名或密码不会使旧授权失效；后端重启后按原学校、区县、届次、班级范围连接新地址查询。

旧版保存的 `education-<连接摘要>` 标记自动兼容为逻辑资源标记，不需要知道旧地址或批量重绑账号。读取和查询不改写数据库、不增加授权版本；管理员下次保存时使用稳定标记。兼容仅作用于同一工作空间、同一学情资源的旧连接标记，其他资源和范围不变。

连接变化会重新加载组织目录并重新校验表结构、权限键及查询计划；如果新库缺少原学校/届次/班级或所需字段，对应查询仍会明确报错，不会扩大到其他范围。查询缓存和历史结果继续按当前连接及发布版本隔离，这与保留原授权分开处理。

页面操作：

1. 使用有权限的管理员账号进入“权限管理 → 教育权限”。
2. 顶部“分级数据权限”直接显示当前工作空间的账号列表，按姓名/账号搜索，支持服务端分页（20/50/100条），不再只取前500个账号。
3. 勾选多个账号，可跨页、跨搜索结果保留选择，一次最多500个。点击“批量授权”，选择共同的市/区县/学校/年级/班级范围及对照能力。
4. 默认追加并保留每个账号原有范围，完全相同的配置跳过；也可明确选择“替换全部范围”。先预览每个账号的变更前后范围、能力、有效期与委派设置，再确认应用。
5. “批量撤销”同样先预览，再确认。即使账号尚未迁移，也会写入新版空授权标记，防止撤销后回退旧权限；已经撤销且没有范围的账号跳过。
6. 各自任教班级不同的老师，点击账号行“管理权限”，在侧栏添加/编辑/撤销多个范围；年级按届次绑定。保留高级CSV导入处理差异化批次。
7. “刷新”清空选择并重新读取目录及账号列表；普通请求复用最多5分钟的元数据缓存。旧版入口默认折叠，仅展开时加载兼容维护界面。

保存新版授权或撤销过新版授权的账号使用新查询校验链路；其他账号暂时保留旧行为，便于逐个迁移。新版账号没有有效授权时拒绝查询，不回退旧权限。

当前固定总览模型支持范围、均分基准和自身排名。总览表没有可靠的考试日期字段，页面暂不提供按日期限制历史访问；若旧文档已有历史日期限制，仍严格拒绝无法证明的查询，不会忽略限制。

已只读检查实际学情库结构及组织目录，并用现有 DataSemantic 真实编译计划验证了本班过滤、年级均分基准、本区排名和本校/全市均分差。真实查询联调仅返回授权范围内的汇总值，没有修改账号授权或输出学生明细。更多指标、派生视图及正式数值验收仍应按发布物单独验证。

## JSONB 文档

```json
{
  "edu_auth_v2": {
    "schema_version": 2,
    "revision": 1,
    "managed_resources": ["1:4"],
    "grants": [{
      "id": "teaching-class-1",
      "workspace_oid": 1, "datasource_id": 4, "level": "class",
      "city_id": "CITY001", "school_id": "SCH001",
      "cohort_id": "COHORT2027", "class_id": "CLASS01",
      "capabilities": ["grade_baseline"], "enabled": true,
      "can_delegate": false,
      "valid_from": "2026-11-10T00:00:00+08:00", "valid_to": null,
      "history_from": "2026-09-01", "history_to": null, "remark": "班主任"
    }]
  }
}
```

通过页面/API 写入。保存锁定用户行并检查全局 revision，仅替换当前空间、数据源的范围，保留其他变量和资源授权。撤销全部范围仍保留 `managed_resources` 标记，防止配置移除后回退旧路径。

支持 city/district/school/grade/class/student。兼任多班使用多条完整元组，不能交叉学校与班级列表。年级绑定学校及届次，学生使用匿名标识。

管理者须为平台管理员，或当前空间管理员且具有效 can_delegate 授权。受限管理员不能管理已有更大授权、超范围委派、延长有效/历史区间或增加未获委派能力。授权变更与现有审计表同事务提交。

同时收口账号与成员管理：停用账号不能继续使用旧JWT；普通成员不能重置他人密码、改变他人账号或自行修改空间管理身份。数据库凭据读取、数据源连接增删改及测试限平台管理员，避免通过获取数据库凭据绕过业务行权限。

## 页面与 API

“权限管理 → 教育权限”的“分级数据权限”面板以账号表格为主入口，支持搜索、分页、多选、批量追加/替换/撤销及逐人管理。共享配置由表单生成批次，管理员无需手写JSON；应用复用现有整批原子写入和审计接口。

API 前缀为 `/api/v1/permission/edu/v2`：

| 接口 | 用途 |
| --- | --- |
| GET /users?page=1&page_size=20&keyword= | 当前空间账号分页、可管理授权摘要及版本；仅管理员/有效委派者可读，超管理范围账号不返回授权 |
| GET /source | 固定学情资源信息，不返回连接地址和凭据 |
| GET /bindings | 兼容接口，仅返回固定学情资源 |
| GET /catalog?refresh=true | 操作者范围内的组织/届次/班级目录，可强制刷新 |
| GET /grants/{user_id} | 当前学情资源授权和 revision |
| PUT /grants/{user_id} | 保存 `{expected_revision, grants}` |
| POST /effective | `{user_id,sql?}`，返回上下文和语义验证，不执行数据查询 |
| POST /batch-bind/preview | `{csv}`，只校验 |
| POST /batch-bind/apply | 重新检查权限和版本后整批原子写入 |

CSV 表头为 `user_id,expected_revision,grants_json`，每用户一行，grants_json 为授权数组并使用标准 CSV 引号转义。授权的资源编号由 `/source` 返回，仅作内部绑定，不由页面用户选择。兼容请求若传入其他数据源编号会被拒绝。批次按用户 ID 顺序锁定，任意一行失败全部不写入。预览不构成永久授权，应用时重验。

## SQL 子集与对照约束

支持能证明的单 SELECT、非递归 CTE、INNER/CROSS JOIN、聚合、窗口和 UNION ALL。每个事实来源均有范围/硬规则保护。透明编译包装可以被识别；相关/标量子查询、外连接、递归、集合差、未审核函数及无法绑定的形态拒绝。

编译器会把本校和全市的共同来源提取成共享CTE。校验器只在验证副本中展开多次使用的透明列投影，保留已有WHERE后分别验证各消费者；聚合、窗口、关联、排序和截断等操作不会按透明投影处理。执行的物理SQL保持编译结果，校验器不补权限条件。每一路扫描、基准释放及最终字段契约仍必须与逻辑证明一致。

- grade_baseline：本校同届次、固定考试，只按批准维度聚合；ROUND 到策略精度，HAVING 同时检查有效样本数和不同班级数。
- city_baseline：本市固定届次和考试，检查有效样本数和不同学校数。
- district_self_rank：本市固定届次、考试和科目，各区县先过样本门槛，再 RANK/COUNT OVER，最后仅保留本区并检查参评区县数。

默认样本数 10、单位数 3、精度 2 位，正式值需业务审核。参照池不能任意拆组、排除某班/校、先截断或另开输出路径。强制旧行规则继续存在；无法映射到语义模型时禁止启用，不能静默忽略。

### 全市基准SQL与错误修正

模型上下文和可修正错误都提供`reference_query_contract`：`metrics`的键（例如`mean_sx`）是指标标识，须展开为`AVG(sx)`等表达式，不是模型字段。默认整体基准只输出ROUND后的审核指标及允许的分组维度，COUNT人数/学生数/学校数仅用于HAVING门槛，不作为结果输出。固定考试和届次后可不分组，不按学校或届次拆分全市基准。

全市池不添加本校、区县、校类或成绩非空等额外人群筛选；AVG本身忽略NULL。本校和全市池先在独立CTE中聚合，释放后再关联计算分差。宿主仍不生成或改写模型SQL。

`failure_stage=sql_validation`表示当前SQL未通过校验，错误同时返回`granted_capabilities`和修正契约；不能据此断言账号没有已授予的`city_baseline`。模型按反馈自行修正，达到原有两次修正上限后停止查询，并说明具体未完成原因；不再弹出让用户反复选择“继续读取”的技术兜底追问。权限失效、物理证明失败等不可修正错误仍立即停止。

## 旧入口及回滚

使用新版授权的账号不能通过旧教育报表/成绩库等接口绕过验证，旧查询 helper 同样检查新版资源标记。尚未迁移的账号保持旧行为。独立维护入口需完成单独的维护授权适配后再向新版账号开放。

旧报告没有当前 v2 指纹时不可读；不能回收用户此前已下载的本地文件。回滚保留授权及资源标记；旧版本无法表达 v2 范围时暂停该数据源，不能恢复默认放行。

上线仍需审核真实映射、绑定账号、完成真实库金标和灰度验收。不能把示例配置或单元测试通过等同于已经上线。

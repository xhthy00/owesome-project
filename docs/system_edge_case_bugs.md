## BUG-2（中）内部 school_id 泄露到用户可见的报告标题

### 复现

同 BUG-1 场景，报告主标题出现 `GZ_19D9D68D`（tb_school.id 内部主键）。

### 根因

[tools.py:3719-3720](../blob/edu/src/agent/education/tools.py)：

```python
title_bits = [p for p in (school_name, class_name, subject_name) if p]
title = f"{' · '.join(title_bits)}班级总览报告"
```

`school_name` 原样拼接，上游传的是内部 ID。

### 附带风险面（同款拼接模式需一并排查）

- `bureau_analysis.py:1007` `f"{exam} · {label}"`
- `line_reach_report.py:748` `f"{' · '.join(title_bits)} · …"`
- 其他用 `"·"` 拼 title/data 的报告工具

### 修复建议

所有报告拼 title / data 前对学校标识做统一归一化：`ID/s_name → tb_school.s_name → 去校码前缀显示名`（如 "A01扬州中学"→"扬州中学"）。建议做一个公共 helper（可挂在 `_resolve_school_for_class_overview` 一类已有解析点），全部报告入口强制走它。

## BUG-3（低）已核实的数值口径与展示小问题（合并记录）

1. **跨年批次误入"今年"**：问"今年考试"，系统把 `2025-11-13` 的 11月期中算进 2026 年。批次表 `tb_exam_batch.exam_time` 有真实时间，涉及年份语义时应按 exam_time 过滤或向用户交代比较范围。
2. **LLM 誊写数字幻觉一例**："11月期中数学均分 89.2"——库内任何口径均为 89.04，无 89.2。治理方向：SQL 结果进结构化通道直出，禁止模型复述时改数；重要数值可加"结果源自查询，禁止四舍五入以外的修改"约束。
3. **排序变化显示格式不一**：部分报告"排序变化"列输出文本（如 `升3名`）而 Word 口径为数字（`3`）。统一一种。
4. **占位符不统一**：空名单行 Word 用 `─`、HTML 用 `—`，导出比对会误判差异。统一字符。

## BUG-4（高）组合达线统计："扬州市"全市行与"A01扬州中学"逐位相同

### 复现

账号 `tanghaoyu`，提问：

> **2026届高三 3月 理科各选择组合达线情况分析**

返回表格中"单位=扬州市"与"单位=A01扬州中学"两行数据**完全一致**（物化生 533/509/95.50%/529/99.25%，物化政 45/38/84.44%/44/97.78%，物化地 67/65/97.01%/67/100.00%），且 物生政/物生地/物政地 三组合全市均为 0 人。全表理科合计仅 645 人。

### 为什么可断定为错

1. 量级：扬州市物理方向一届应有数千人，645 人只是单校体量；
2. 物生政、物生地、物政地在全市为 0 不可能（江都/高邮/宝应等多校开设）；
3. 连 97.01% 这类带小数比率都逐位相同，必为同源数据被贴了两个标签。

### 可能根因（取数路径待定位）

a. **权限/过滤错位**：问句含"扬州市"，管道本应做全市聚合，实际 WHERE 被 school_admin 权限收敛替换成了 school_id 过滤，但仍按问句保留"扬州市"行标签 → 重点排查 `line_reach_report.py` 及 NL2SQL 生成 SQL 的条件拼接；
b. 维表存在"扬州市"汇总单位、事实表无对应汇总记录，取空后回退到第一条学校记录；
c. 渲染层仅有一行结果，被同时填入"全市"和首所学校两行。

另需排查导入侧：是否有一个名叫"扬州市"的单位实体挂了扬州中学的学生成绩。用
`SELECT 单位, COUNT(*) FROM 成绩明细 WHERE 考试='2026届高三3月' AND 组合='物化生' GROUP BY 单位`
即可判别问题在查询层还是数据层。

### 修复建议

1. 同一条链路内，市级行与校级行必须出自同一 GROUP BY 的不同汇总分支，禁止两套独立取数互相拼标签；
2. 增加输出前断言：任一父级（市/区县）汇总行与任一子级（学校）行逐值相等且人数>0 时告警或拒绝输出（可泛化为父子聚合一致性校验）；
3. 若权限语义就是 school_admin 仅可见本校，应在意图层明确回复"无全市查看权限"，不得用本校数据冒充全市。

### 回归验证

同账号同问句复测：扬州市行应等于全部在库学校之和；至少不再与扬州中学逐位相同。

## BUG-5（中）班级/学生统计引擎缺陷集（借 BUG-1 误出的《高三(1)班综合分析报告》发现）

> 该 HTML 报告本身即 BUG-1 的错误产物（凭空编造"高三(1)班"），但它暴露的是班级综合报告工具的**算法层通用缺陷**：班名合法、报告正常触发时同样成立，故单列记录。

1. **缺考计 0 分并参与全部统计（最重，直接影响教学决策）**：学生 F5DC0D4A 期中 638 → 期末 228 → 3月/5月缺考按 0 计入，得出"总分下降 -638 分，需立即干预"；其 228 分把期末标准差拉至 57.27（其余 51 人区间 594–662，正常约 15），连带第一章"标准差 12.07→17.79、分化加剧 +5.72"的核心诊断失真；全体轨迹图绘出 638→228→0→0。缺失样本应从趋势/标准差/偏科度等计算中剔除并单独标注。
2. **水平分布饼图与档案卡矛盾**：饼图 A=50、B=1、D=0，合计 51≠52；档案卡中确有 1 名"D (待提升)"学生未计入。
3. **进退步判定前后不一**：卡片与第四章按阈值将 +2.0/+2.5 判为"稳定"（进步2/稳定5/退步45=52人），第五章"进步最快 TOP5"却又按原始 Δ 排序把这两人列为进步生，且号称 TOP5 实际仅 4 行。
4. **相关性结论文案错乱**：固定模板文案里 r≈0.49 被称"较弱"、r≈0.52 被称"对总分排名影响最大"（阈值口径随意），且化学与生物两科被同时写成"最大"；对不同考试的相关系数直接取平均也欠妥。
5. **跨考试裸分直比，无难度校正、无外部参照**：全班均分期中 644 → 3月 598 → 5月 621 属试卷难度位移，却被直接判定"45 人退步""生物均分降 11.6 分需探究教学效果"，每名学生档案随之批量打上【警惕下滑】。趋势比较应改用市排名/标准分等标化口径（市级报告数据已在库内，可直接对标区分"卷难"与"真退步"）。
6. **个人档案可用性**：【小题补漏】如"第13题得分率0.0%"不注科目与知识点，六科各自都有第13题，教师无法执行；所引用的题目得分率分母呈 n/17 规律（全班 52 人，口径不明）；考试名截断显示为"2026届高三5…"。

### 修复建议

第 1、5 条优先：缺考状态落独立字段并全链路显式区分；趋势对比改标化口径，并在图表脚注声明比较基准。第 2–4 条为输出一致性 bug，增加生成后的交叉校验即可拦截（各区段人数守恒、阈值定义唯一化）。第 6 条补题目元数据（科目/知识点）与考试名全长。

### 回归验证

用一个真实存在的班级重新生成一期班级综合分析报告，逐项对照上述 6 条。

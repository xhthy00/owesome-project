# 学情分析权限改造方案

日期：2026-11-10。状态：核心实现已落地，真实数据源启用和金标验收待完成；已实现行为及启用步骤见[实现与启用](education_permission_v2.md)。查询执行采用“模型显式生成带权限语义 SQL、宿主验证、DataSemantic 编译、宿主执行”；详细设计见[模型生成带权限语义 SQL：详细落地方案](model_generated_permission_sql_plan.md)。

本方案依据“学情分析智能体账号权限”图片及当前仓库实现制定。目标是覆盖市、区县、学校、年级、班级五类业务范围，并支持受控的上级汇总对照。学生角色继续兼容。方案中的建议默认值不表示业务已确认；进入对应功能开发前，应将最终选择写入权限矩阵和验收用例。

## 1. 改造结论与边界

复用现有 JWT、平台角色、工作空间、行列规则、DataSemantic 查询规划及审计基础。在当前应用内增加统一教育授权服务、结构化范围授权和确定性 SQL 验证器，不增加独立权限微服务。业务计算、普通范围条件、参照池和最终输出过滤均由模型写入语义 SQL，DataSemantic 不负责用户权限生成。

实施重点：

1. 将职务名称与数据范围分开。市局领导、教研员等职务可以使用同一范围模板，不需要逐个建立后端角色分支。
2. 增加区县、年级及届次绑定，学校、班级使用稳定标识，授权绑定到工作空间和数据源。
3. 普通查询始终在本范围内执行；上级汇总和排名也由模型生成完整语义 SQL，通过受控统计能力及数据流规则验证。
4. 模型缺少权限条件时由宿主拒绝并返回错误，交给模型重写；新模式不由宿主或 DataSemantic 自动补写权限 WHERE。语义和物理验证使用同一授权义务及审核映射。
5. 聊天、直接 SQL、报告、导出、历史结果及后台任务使用同一授权边界。

本期主要改造读取权限及授权管理。成绩导入、考试维护等业务写入不随“可读全市”自动开放；沿用各自功能权限，检查其入口不会绕过本期边界。

## 2. 现状与必须处理的问题

| 当前实现 | 改造要求 |
| --- | --- |
| `config/education_permission.json` 只有 `bureau_admin / school_admin / teacher / student` | 补充区县、年级模板，保留旧代码兼容入口 |
| `EduScope` 存在用户全局 `system_variables`，没有区县、届次、工作空间和数据源维度 | 新建按工作空间、数据源绑定的授权记录 |
| `query_permission.py` 根据聚合、窗口排名等 SQL 形状删除范围条件 | 新模式不再调用行权限补写/删除；模型显式写条件，宿主验证普通范围及受控统计数据流 |
| `SemanticQuery._verify_row_filters` 重新拼装谓词，并按语法片段检查 | 先验证模型语义 SQL，再按同一授权义务和审核映射核验编译后的实际读取及输出路径 |
| 总览表学校标识会被展开为 ID/名称匹配 | 先建立数据源标识映射，再使用精确标识匹配；逐步退出运行时名称模糊匹配 |
| 工作空间 Header 只定位空间，成员校验尚未启用 | 校验空间成员关系和数据源授权，不能通过修改 Header 切换访问边界 |
| 任一空间管理员可进入教育权限管理 | 管理员只能管理其获授权空间和数据源，授予范围不得超出其可委派范围 |
| 已有会话权限指纹及历史隔离 | 扩展指纹，纳入新授权、维度映射、策略版本及有效期 |

上述为代码层面的现状。上线数据源中学校码、区县、届次的实际取值及覆盖率仍需核验；参考 DDL 和旧权限文档对 `overview.xx` 的描述存在差异，不能直接认定某一种描述就是线上事实。

## 3. 目标业务权限矩阵

“本范围数据”同时包括本范围内的汇总及现有可见明细，学生身份信息继续受列权限和脱敏规则约束，不因范围升级新增个人敏感字段权限。

| 业务范围 | 普通查询可见范围 | 对照能力 | 明确禁止 |
| --- | --- | --- | --- |
| 市级 | 授权城市内所有区县、学校、年级、班级 | 全市统计、各区县/学校排名、同口径历次趋势 | 其他城市或未授权数据源 |
| 区县级 | 本区县学校及其下属年级、班级 | 全市整体基准；本区县在同城区县中的自身名次及参评数 | 其他区县逐项达线率、均分、学校榜单和学生明细 |
| 学校级 | 本校各年级、班级 | 全市整体基准；默认不开放跨校排名，单独批准时只返回本校名次 | 其他学校指标列表及学生明细 |
| 年级级 | 本校授权届次/年级及下属班级 | 默认限本年级内部各班比较 | 本校其他年级和其他学校数据 |
| 班级级 | 本校被明确授权的班级 | 本校同届次对应年级的整体均分、达线率等基准 | 未授权班级逐班指标、排名明细和学生明细 |
| 学生兼容 | 本人被授权的成绩 | 默认不新增上级基准或排名能力 | 其他学生明细 |

岗位到范围映射：

- 市局领导、市教科院领导、质量监测人员、大市高中教研员 → 市级。
- 区县教育局领导、区县教研人员 → 区县级。
- 校长、教学分管校长、教务主任、教务员 → 学校级。
- 年级分管校长、年级主任、年级组长、备课组长 → 年级级。
- 班主任、一般任课教师 → 班级级；兼任多班时逐班显式授权。

建议默认值与待定业务边界：

1. 班主任的“年级均分”默认指本校同届次对应年级，不包括跨校年级；下级对照允许的指标只取审核后的目录。
2. 区县用户允许“本区全市第几”，返回自身名次和参评数，不返回其他区县得分；其他区县名称目录也不作为该统计结果附带返回。
3. 学校用户的全市整体基准用于承接现有功能；是否继续开放本校跨校名次需明确确认。已有默认“同层次学校排名”的逻辑不能自动带入新策略，全市/同层次是统计口径，应明确标注。
4. 图片没有限定任课教师只能看所教学科，本期按授权班级内现有可见学科处理。如需学科限制，新增独立学科条件，不从职务名称推断。
5. 历次趋势必须处于授权学校、届次/班级及可访问历史区间内，不能因“上一场考试”切换至其他届次。
6. 小样本汇总和反复差分可能推断其他单位数据。对照仅开放固定完整人群，不开放“除去某班/某校”等任意子集；上线前确定最小参评人数、单位数及精度。低于阈值时不输出基准或名次。

## 4. 权限模型及持久化

### 4.1 平台角色、业务范围、统计能力分别表达

- 平台角色决定系统维护、授权管理等操作。
- 范围授权决定普通查询可以读取哪些业务行。
- 统计能力决定是否可请求年级基准、全市基准、自身排名等结果。
- `ds_rules / ds_permission`、字段可见性和脱敏继续作为约束，与授权范围叠加。

平台管理员维护身份不能直接代表市级业务身份。建议教育业务入口默认也要求显式业务范围；既有管理员豁免以独立迁移开关承接，正式验收前退出默认豁免。维护场景如确需越权读取，另设明确、可审计的维护入口。

### 4.2 建议数据结构

不新增表，使用现有 `sys_user.system_variables.edu_auth_v2` 作为 v2 授权事实源。文档包含 schema_version、全局 revision、managed_resources 和 grants 数组；每条授权保存以下信息：

| 字段 | 用途 |
| --- | --- |
| `id / workspace_oid / datasource_id` | 用户由所属 sys_user 行确定，授权显式绑定资源，不设全局通配 |
| `level` | `city / district / school / grade / class / student` |
| `city_id / district_id / school_id` | 稳定组织维度；下级必须属于相应上级 |
| `cohort_id / class_id / student_id` | 届次、班级、学生范围；使用按数据源命名空间解析的稳定标识 |
| `capabilities / can_delegate` | 审核后的基准/排名能力及受限委派资格 |
| `valid_from / valid_to / enabled` | 授权生效、到期和撤销；到期按当前请求时间判断 |
| `history_from / history_to` | 可访问考试历史区间；与授权有效期分开表达 |
| 文档 `revision`、授权 `remark`、现有审计日志 | 乐观版本检查、备注及同事务变更追踪 |

一个班级授权一条记录，兼任多班使用多条记录。不把学校列表和班级列表分别做 `IN` 后组合，避免出现“学校 A 的班级授权被套用到学校 B”的交叉扩权。

组合原则：同一用户的有效范围按完整授权记录取并集，之后与强制行规则取交集。统计能力必须绑定到产生该能力的授权记录及其父范围，不能把 A 校授权与 B 校的基准能力拼接使用。列表、单用户编辑、CSV 导入均调用同一校验和保存服务。

能力模板保存在版本化的 `config/education_permission_v2.json`，初期只支持审核后的模板，不做任意策略表达式编辑器。新增角色不依赖 JSON 单点修改，后端 schema、校验、策略解析及迁移同步更新。

### 4.3 维度目录与历史归属

优先复用业务库和 DataSemantic 已发布维度。缺少稳定标识时，增加应用侧维度映射表，向模型提供稳定逻辑键及其授权值，并用于宿主核验物理映射，不强制给整个系统新建通用组织树。业务查询中的权限条件由模型生成。

- 城市/区县：维护稳定 ID 与数据源字段值的精确映射，不能只存显示名。
- 学校：统一 `tb_school.id`、学校展示名、`overview.xx`、指标表学校码等映射。一个别名对应多校时拒绝绑定，输出待修复记录。
- 年级：UI 展示“某届·高三”；底层绑定稳定届次，并记录学年、考试发生时的年级映射。优先核验现有 `tb_exam_batch.jc / tb_exam.jc`，不靠考试名称字符串授权。
- 年级历史访问建议按同届次承接：获准历史区间内，这一届过去的高二成绩可用于趋势；当前另一届的高二不在范围内。新学年继续负责同一届还是改负责新一届，由授权变更决定，不按“高三”字样自动漂移。
- 班级：标识包含学校和届次语义，维护考试时的班级归属；不能只凭“高三(1)班”匹配历年所有同名班。
- 跨年级任职、转班、区划调整：根据明确的历史访问规则解析到考试快照，不能把当前组织关系无条件套用到全部历史。
- 缺少届次或无法唯一映射的旧数据先列入待修复清单。只有经确认的映射才能进入授权目录；无法解析时拒绝相关查询。

## 5. 查询执行设计

### 5.1 统一授权上下文

新增 `SemanticAuthorizationContext`，按当前身份、工作空间、数据源加载，至少包含有效授权记录、逻辑字段级权限义务、允许操作、可用统计能力、列约束、策略版本、维度映射版本和权限指纹。模型读取该结构后生成带权限的完整语义 SQL；服务端重新读取的授权事实才是判定依据。

身份或授权加载失败、账号禁用、范围不完整、数据源越界、授权已到期时拒绝数据查询。公开参考维度单独登记，不再以“没有可挂载的范围列”为由默认放行未知业务表。候选学校/班级目录、考试选项和澄清问句中的候选值也按该上下文过滤。

### 5.2 普通查询

1. 模型根据可信上下文，在每个实际读取的语义来源上写出完整范围及强制条件。
2. 宿主绑定 AST 作用域和列，验证表别名、CTE、支持的子查询/UNION/JOIN 各读取路径，确保聚合之前被授权范围保护。
3. 有效 `ds_rules` 映射成逻辑义务供模型表达并接受验证；无法映射的硬规则阻止该发布物启用，不被忽略。
4. 语义验证通过后，才将完整 SQL 交 DataSemantic 编译；服务不读取账号授权，也不添加权限谓词。
5. 宿主按审核发布映射验证实际物理来源、过滤位置及最终输出。不修改权限条件，缺失或无法证明时拒绝并交模型重写。
6. 只读执行，应用脱敏及结果契约，检查权限仍有效后返回；schema 限定/行数限制等 SQL 操作之后也重新核验最终计划。

有 `AVG/COUNT/SUM/RANK` 的普通 SQL 仍只计算授权范围。校级预计算表缺少班级/届次维度时，不能用它回答班级或年级范围问题；应选择可正确过滤的事实表，无法实现则拒绝。

`scope_guard.py` 保留为解释和提前拒绝的体验层，最终授权以服务端计划为准。不能仅靠中文校名或班名抽取实现访问控制。

### 5.3 受控统计能力

基准与排名继续使用统一 `query_semantic`，由模型写出参照池、聚合、窗口及最终自身过滤。宿主按能力模板验证；不新增由后端固定写业务 SQL 的基准工具。能力名称或 CTE 名只能表明意图，不能代替实际 SQL 数据流证明。

首批能力：

| 能力 | 可调用范围 | 扩展统计范围 | 输出边界 |
| --- | --- | --- | --- |
| `grade_baseline` | 班级 | 所属学校同届次对应年级 | 年级整体指标；本班对照指标及差值可一并返回，无其他班逐班行 |
| `city_baseline` | 区县；学校按最终模板 | 授权城市对应考试人群 | 全市整体指标，无区县或学校拆分 |
| `district_self_rank` | 区县 | 同城同考试的合规区县池 | 本区指标、自身名次、参评单位数，无其他区县行 |

执行顺序：模型读取目标及参照池权限义务 → 生成含完整条件和最终输出过滤的 SQL → 宿主验证每个来源、聚合/窗口及输出路径 → DataSemantic 编译 → 宿主核验物理计划 → 数据库执行完整查询 → 校验输出契约 → 返回模型。

模型不能通过 SQL 声明扩大参照池。只有服务端能力允许的范围可被内部统计使用；已有通用强制行列规则不能被删除。若旧 `ds_rules` 里存放了与新范围授权重复的学校/班级条件，迁移时逐条确认后转为范围记录，不能由运行时猜测哪条可忽略。硬限制导致参照池不完整时，不冒充“全市排名”，返回口径不可用或明确获准的实际池口径。

统计结果必须带 `metric_code / exam_ref / target_scope / reference_scope / population_definition / policy_version`，输出结构固定。对照输出的精度、样本阈值在服务端应用；模型上下文、工具日志、SQL 返回字段、图表和报告均不携带其他单位的中间结果或排名池 SQL 文本。

参照池只在数据库内部被完整查询消费，不先返回模型。最终输出只允许普通授权数据或经过证明的整体基准/自身排名，防止模型从其他 CTE、标量子查询、排序或存在性判断泄漏池中其他单位数据。

### 5.4 模型修正与支持边界

模型漏写或错写权限时返回结构化错误，定位到来源、作用域和缺失字段；默认最多两次权限修正且消耗现有总预算。授权失效或实际越权不引导绕过。验证器首期支持有限 SQL 子集，不能证明的复杂形态拒绝；不使用另一个模型作为最终授权裁判。

详细 SQL 示例、授权 JSON、语义与物理验证算法、错误码及当前 SSE 输出风险见[详细落地方案](model_generated_permission_sql_plan.md)。新数据源模式不再调用旧行权限注入器，`execute=False` 仍完成全链校验。

### 5.5 统计口径

- 达线率按 `SUM(reached_count) / SUM(candidates)` 重算，不能直接平均学校达线率。
- 均分按有效总分/有效人数计算或加权，不能直接平均各班均分。
- 排名需明确指标、方向、并列规则、参评单位、考试/选科/学生性质及学校类型；建议并列使用 `RANK`，最终由指标目录固定。
- 趋势按考试时间选择同届次、同定义可比考试；每一场都重新检查授权。
- 缺考、零分、班级样本阈值等沿用审核后的指标定义，并在对照两侧一致执行。

## 6. 接口与管理页面

复用“权限管理 → 教育权限”，保留旧 API 作为兼容适配入口，新增 v2 数据结构与接口：

| 建议接口 | 职责 |
| --- | --- |
| `GET /permission/edu/v2/profiles` | 范围及统计能力模板 |
| `GET /permission/edu/v2/catalog` | 根据操作者管理范围返回城市、区县、学校、届次、班级目录 |
| `GET/PUT /user/{id}/edu-grants` | 查询或替换完整授权集合；写入携带版本，防止覆盖并发修改 |
| `POST /permission/edu/v2/batch-bind/preview` | CSV 解析、ID 解析、重复/越界检查及变更预览 |
| `POST /permission/edu/v2/batch-bind/apply` | 对已校验批次按同一服务执行，输出逐行结果及审计记录 |
| `POST /permission/edu/v2/effective` | 返回最终范围、允许能力、拒绝原因、输出边界及验证义务；可验证模型 SQL，不补写权限条件、不执行数据查询 |

管理页要求：

- 根据所选业务范围联动选择上级组织、学校、届次和班级，使用 ID 保存并展示中文名称。
- 支持一个账号多条完整授权、有效期、历史范围和兼任岗位备注。
- 统计能力以审核模板展示，管理员能看出“只允许整体年级基准，不允许其他班逐班指标”。
- 预览同时显示允许与禁止示例，包括图片中的原始问句。
- CSV v2 包含工作空间、数据源、范围层级、稳定维度 ID、能力模板、有效期和历史区间；旧 CSV 经同一迁移规则解析，不能默认绑定任意数据源。
- 普通用户可查看自身有效范围；管理员可查看和管理授权范围内的目标用户。读取其他用户授权信息同样校验管理权限。

工作空间管理员的教育授权管理资格需要由平台明确委派。管理 UI 隐藏按钮仅用于体验，API 对目标用户、数据源和每条拟授予记录逐项校验，禁止自行提升或通过兼任空间绕过边界。

## 8. 历史结果、撤权和旁路控制

- 查询、工具结果、会话恢复、结果缓存按用户、工作空间、数据源、有效授权、策略及语义发布版本隔离。
- 每次工具执行重新确认有效授权；长任务完成后、流式结果发布前再次检查权限版本和有效期。撤权或到期后不继续输出旧权限下的结果。
- 原有 `authorization_fingerprint` 保留并扩展；权限发生变化时不把旧结果、旧摘要、已卸载工具结果重新载入模型。
- 报告生成、读取历史报告、下载导出均重新鉴权。第一期可采用保守策略：权限指纹不匹配时旧报告不可下载，允许用户按新范围重新生成。
- 受保护报告通过鉴权下载或短期授权链接提供；不得将成绩报告留在绕过权限的公共静态路径。需扫描当前实际报告存储/分发方式。
- 后台报告/预警任务绑定明确的服务主体和限定范围；缺少用户 ID 不能意味着无限范围。
- 对 `execute_sql` 直连调用建立清单，区分基础元数据、维护任务、学生业务查询，所有面向用户的业务读取接入新执行服务。
- 授权写入与变更记录在同一事务提交，避免仅靠现有异步审计写入丢失授权变更。查询访问日志可以复用异步审计，禁止记录未经授权的排名池明细。

## 9. 迁移和上线

1. **盘点与试迁移**：导出旧教育范围、规则组、管理员身份、用户空间关系及实际数据源标识映射，只生成迁移清单。
2. **逐条映射**：`school_admin → school`；`teacher → 每个可唯一解析班级一条 class`；`student → student`；`bureau_admin → 显式 city`。旧记录缺失数据源、城市、届次或班级标识时，进入待确认清单，不自动赋予所有资源。
3. **权限规则核对**：区分可迁移的重复范围条件与必须继续生效的业务硬限制；记录旧/新权限差异，任何扩大范围都需要显式业务授权。
4. **影子计算**：离线合成数据和请求计划上比较旧/新授权决策，允许时才执行当前生效策略。影子阶段不得为了比较而将扩围数据返回用户或记录原始明细。
5. **按数据源灰度**：先启用目录/绑定，再启用普通查询和受控统计，最后接通报告/导出；每个灰度数据源整条用户读取链路一起切换，未接入入口暂时拒绝其业务数据读取。
6. **切换事实源**：启用 v2 的数据源停止读取旧范围作为回退；旧 API 写入也通过 v2 服务。迁移幂等、可重复核对并保留变更记录。
7. **回滚边界**：授权数据和映射快照可恢复。代码回滚不得恢复未经证明安全的聚合放宽或默认放行；必要时暂停受影响的数据源查询，保留授权管理和修复入口。

本期不在生产直接批量改绑账号。实施前形成可审阅的迁移清单，实际切换属于后续发布操作。

## 10. 验收矩阵

测试采用至少两个工作空间、两个城市、同城两个区县、每区县两所学校、每校两个届次、每届次多个班，以及兼任多班和管理范围不同的账号。构造同名班、同名/别名学校和区划变化样本。对照统计阈值测试另外生成足够单位和人数，避免小数据集掩盖输出约束。

| 编号 | 身份/请求 | 期望 |
| --- | --- | --- |
| A01 | 市级：全市达线率、各校排名及近三次变化 | 只包含授权城市；各次考试口径可比 |
| A02 | 市级：查询另一城市数据或更换数据源 | 拒绝 |
| A03 | 区县：本区达线人数、达线率、全市位次 | 正确返回本区指标、自身位次与参评数 |
| A04 | 区县：其他区县达线率/均分及语文排名明细 | 拒绝；工具结果与报告均无其他区县行 |
| A05 | 区县：本区各校均分与全市整体差距、薄弱学科 | 返回本区学校及整体基准，无外区学校明细 |
| A06 | 学校：本校各班达线率、临界生和学科短板 | 限本校，学生信息仍受原列权限/脱敏约束 |
| A07 | 学校：点名其他学校或要求其他高中成绩做校际比较 | 拒绝 |
| A08 | 年级：本年级各班均分、达线人数和临界生 | 限本校被授权届次/年级 |
| A09 | 年级：本校其他届次年级，或跨届次同名班 | 拒绝；同届次过往年级仅在获准历史区间内可查 |
| A10 | 班级：本班各科均分与本校年级均分差距 | 只返回本班及整体年级基准，不含其他班逐班值 |
| A11 | 班级：比较未授权的高三(2)、高三(3)班，或查询“其他各班” | 拒绝；不能只依靠识别出显式班名才拦截 |
| A12 | 同一老师在 A、B 学校各有班级授权 | 只出现每条授权对应的班级，不出现交叉组合 |
| A13 | 学生、无教育范围、禁用账号、过期/无效授权 | 学生限本人；其余拒绝业务数据查询 |
| A14 | 普通成员伪造空间 Header；A 空间管理员管理 B 空间授权 | 拒绝 |
| A15 | 自助改教育范围、给自己增加统计能力、越界批量导入 | 拒绝；合法批次有逐条变更记录 |
| A16 | CTE、UNION、子查询、JOIN、自连接、窗口函数、学校别名映射 | 支持子集内每条读取/输出路径可证明；参照池受能力约束，缺条件不由后端补写，不支持形态拒绝 |
| A17 | 校级预计算指标回答年级/班级；未登记事实表；计划解析失败 | 不降级到更大范围或无过滤执行 |
| A18 | 行列规则叠加、窗口排名、`SELECT *`、被隐藏列参与统计 | 强制规则持续生效，不因统计能力移除限制 |
| A19 | 撤权后继续追问、恢复会话、读取卸载结果、下载旧报告 | 不再返回旧范围数据；按新范围重新查询/生成 |
| A20 | 查询期间撤权/到期；后台任务缺失主体 | 发布结果前拒绝，无数据继续流出 |
| A21 | 尝试获取基准底层 SQL、逐步排除其他班、低样本差分 | 无跨范围 SQL/中间结果；超出固定能力或低于阈值时拒绝 |
| A22 | 达线率、加权均分、并列名次、历次考试切换 | 与手工基准数据一致；每次考试独立鉴权 |
| A23 | 聊天、直接 SQL、报告 API、批量报告、图表、预警和导出 | 同一账号边界一致，活跃入口无旁路；模型 SQL 新增验收见详细方案 M01–M17 |

每项既检查最终回答，也检查 SQL 执行边界、返回字段、工具结果、日志和生成文件。越权查询应有稳定拒绝码，不以偶然的 SQL 错误或空结果作为授权通过证明。

现有回归基线：前一轮运行相关 30 项本地测试，29 项通过，1 项会话摘要提示词断言失败。正式实施时先记录或单独修复该既有失败，新增权限测试不以关闭二次校验、跳过授权服务的 mock 作为通过依据。

| --- | --- | --- | --- |
| P0：实际计划原型 | 核验标识/届次及能力矩阵，用三类模型 SQL 检验真实 DataSemantic 编译结果 | 本校过滤、年级基准、本区排名可由宿主验证，不改编译器权限逻辑 | 2–3 人日 |

## 12. 完成定义

- 图片中所有允许问句在对应账号下可以正确完成，所有禁止问句稳定拒绝。
- 区县、年级为正式范围，支持兼任、历史届次及到期撤权。
- 普通查询、受控统计、强制行列规则的组合有唯一服务端解释；业务语义 SQL 和权限条件由模型生成，宿主只验证，不调用 DataSemantic 或自动注入器代写缺失权限。
- 其他单位的明细和中间排名池不进入无权账号的模型上下文、工具结果、缓存、日志或文件。

- 旧账号迁移可核对、可追溯；新旧链路切换不会扩大已授予范围。

# 让"AI 元素"突出生动 —— 整体改进建议方案

> 背景：系统整体演示后，领导反馈"AI 元素不够突出生动"。
> 本文基于现有代码盘点（前端 `frontend-react/`、后端 `src/agent/`、报告模板 `src/agent/resource/templates/education/`），给出可落地的改进建议。
> 目标不是新增多少 AI 算法，而是把系统已有的 AI 能力"显性化、生动化、可感知化"。

---

## 一、现状诊断：AI 能力与 AI 感知之间的落差

系统底层的 AI 能力其实很扎实，问题在于**界面没有把它们讲出来**：

| 已有 AI 能力 | 现状呈现 | 问题 |
|---|---|---|
| NL2SQL（自然语言生成 SQL） | 只在步骤列表里显示 SQL 文本 | 普通用户看不出"这是 AI 写的 SQL" |
| 四 Agent 协作（规划→分析→制图→总结） | `AgentPipeline.tsx` 4 个小胶囊 | 太小、太静态，领导看不到"AI 团队在工作" |
| SSE 流式执行（plan/step/result） | 进度条 + 步骤分组 | 缺"思考过程"文字，`Thinking...` 还是英文 |
| 九类学情报告 + ECharts | 完整图表化报告 | 呈现是"报表感"，不是"AI 感"，缺 AI 解读 |
| 异常预警（临界生/退步/偏科） | 独立菜单入口 | 被动等待用户进入，缺主动触发与 AI 说明 |
| 报告改进建议区 | 埋在报告中后段 | 未上浮为"AI 洞察"，价值感不足 |
| 输入框工具（语音/技能/资源） | `ToolsBar.tsx` 图标占位 | 点击无反应，演示时反而减分 |

**一句话结论**：系统缺的不是 AI 能力，而是"AI 叙事层"——把 AI 的**思考、推理、协作、解读**显性化地讲给用户（尤其是领导）看。

---

## 二、改进主线（四句话方针）

1. **过程外显**：让 AI 的思考过程可见（推理文字、Agent 协作动画、SQL 生成过程）
2. **结论外显**：让 AI 的产出有"AI 口吻"（报告顶部的 AI 总结、AI 建议、AI 解读）
3. **视觉外显**：让界面有"AI 气质"（品牌化 AI 标识、动态光效、数字动画）
4. **交互外显**：让交互入口有"AI 温度"（语音提问、追问推荐、主动预警）

---

## 三、分层改进方案

### P0 —— 本周内可做（改动小、感官回报大，建议优先）

#### 1. Agent 工作台升级：从"4 个小胶囊"到"AI 团队工作台"

**现状**：`frontend-react/src/components/chat/AgentPipeline.tsx` 渲染 4 个静态胶囊（规划→分析→制图→总结），只有"思考中/已完成"状态色。

**改进**：
- 在对话流中把 AgentPipeline 放大为独立"AI 工作台"卡片，展示：
  - 每个 Agent 的**当前动作文案**（如"正在解析需求""正在生成 SQL""正在核对数据口径""正在绘制图表""正在撰写总结"）；
  - 每个 Agent 的**耗时**（`xx.xs`），结束即停止；
  - 整体进度环/进度条（已完成 Agent / 总数）；
  - Agent 之间的连线用动态流光/粒子动效。
- 后端已在 SSE 中下发 plan/step/result 事件（`useChat.ts` 的 `ExecutionStep` 含 `title/detail/progressPct/rowCount`），前端只需把 `detail` 用打字机效果流式渲染，即可让领导看到"AI 正在一步步思考"。

#### 2. 思考过程（reasoning）流式展示

- 现状：`OpenCodeSessionTurn.tsx` 在无回复时显示英文 `Thinking...`。
- 改进：
  - 全部改为中文文案（"正在理解您的需求…""正在查资料…""正在写 SQL…""正在核对结果…"）并轮播；
  - 若 LLM 支持输出推理内容，把推理摘要经 SSE 下发，前端用 `useTypewriter.ts`（已存在）打字机展示；
  - 回复正文也使用打字机流式输出（`useTypewriter` 已实现，接上即可）。

#### 3. 首页（探索广场）升级为"AI 能力橱窗"

**现状**：`frontend-react/pages/index.tsx` 标题 + 输入框 + 4 张静态示例卡。

**改进**：
- 能力卡片升级为 4 张**动态能力卡**，每张配图标动效 + 一句话说明：
  - NL2SQL：一句中文 → 自动生成 SQL
  - 多智能体：规划/分析/制图/总结协同作战
  - 自动报告：9 类学情报告一键生成
  - 主动预警：临界生/退步/偏科自动发现
- 推荐问题动态化：从后端"最近热门问题"接口取（可先用会话历史聚合），比写死的 4 条更有说服力；
- 增加一个"演示模式"入口：一键播放带标注的 AI 全流程（配合演示时使用）。

#### 4. 报告增加"AI 洞察"首屏

**现状**：报告模板（`src/agent/resource/templates/education/*.html`）首屏是标题 + KPI 卡，"改进建议区"（`reportRecommendations.ts` 提取的 `data-edu-section="recommendations"`）埋在报告中后段。

**改进**：
- 在报告**最顶部**加一张"AI 分析摘要"卡，四段式自然语言：
  - 一句话结论（如"本班均分 78.2，较上次提升 3.5 分，处于年级中上水平"）；
  - 亮点发现（1-2 条）；
  - 风险提示（1-2 条）；
  - 行动建议（1-2 条，直接复用现有建议区内容）。
- 摘要由 LLM 基于报告数据生成（后端 `orchestrator.py` 已有 summary 步骤，扩成结构化摘要即可）；
- 前端做"AI 摘要"角标（小机器人图标 + "AI 生成"字样），强化感知。

#### 5. 执行过程可视化增强（对话页）

**现状**：`ChatContentContainer.tsx` 已有 plan/step/result 分组与进度百分比。

**改进**：
- SQL 步骤用语法高亮块展示（可引 `prismjs`/`highlight.js`），并加"由 AI 生成"标签；
- 步骤徽标显示**行数、耗时**（`rowCount` 字段已存在）；
- 步骤状态切换加过渡动画，完成时打勾并轻微高亮闪烁；
- "点击步骤回显对应报告"能力已有（`runId` 关联），做成显眼交互提示："点击查看该步骤产出的报告"。

### P1 —— 2-4 周（把 AI 入口做"活"）

#### 6. 语音提问落地
- `ToolsBar.tsx` 语音按钮目前是空占位，演示时点开没反应反而减分；
- 接入浏览器 Web Speech API 或云端 STT，语音输入后回填输入框；
- 演示话术："不用打字，直接说'分析一下高三(10)班数学成绩'。"

#### 7. 报告追问（对结果继续对话）
- 报告生成后，在报告卡片下方给出 3 个"追问建议"（由 LLM 根据报告内容生成）：
  - "为什么临界生增加了？"
  - "哪几个知识点失分最集中？"
  - "给出 3 条具体的提升建议"
- 点击即发起新一轮对话并带上下文，展示"多轮对话能力"。

#### 8. 一键解释 SQL / 解释图表
- 每个 SQL 块右上角加"解释"按钮，点击后 AI 用中文讲解该 SQL 做了什么；
- 每个图表加"AI 解读"按钮，生成 1-2 句图内关键信息（比让领导自己看图更有冲击力）。

#### 9. 异常预警"AI 说明"
- 异常提醒页（`anomaly-alerts`）每条预警增加"AI 说明"：为什么预警（数据依据）、影响范围、建议行动；
- 后端 `alert_service.py`/`school_intervention.py` 已有检测与干预逻辑，补充一段 LLM 生成的说明文案即可；
- 增加"预警被 AI 发现"的引导：在首页/报告页对存在预警的对象做浮层提示，展示"主动发现"能力。

#### 10. 对比演示模式（传统 BI vs AI）
- 做一个演示页/演示模式：左边"传统方式"（要懂 SQL、要手动找数据、要手动做图，步骤列 5-6 步），右边"AI 方式"（一句话 → 报告，1 步）；
- 这种"前后对比"对领导最有冲击力，适合放进演示收尾。

### P2 —— 1-2 个月（把 AI 做成体系）

#### 11. AI 品牌形象与人格化
- 统一"启明 AI"品牌：logo 动效、AI 助手命名、欢迎语人格化；
- 对话中 AI 回复带人格化口吻（可配置 prompt 中的 persona），让领导感受到"有温度的 AI"；
- 增加 AI 状态提示（正在专注分析 / 正在核对数据），配小动效。

#### 12. 报告语音播报 / AI 数字人
- 报告生成后一键"AI 播报"，TTS 朗读 AI 摘要，配合大屏演示效果极佳；
- 有条件可做简单的数字人形象（不推荐投入过大，语音 + 摘要已足够）。

#### 13. 文档知识库（RAG）
- 接入学校制度文档、教学大纲等，支持"上传文档 → 结合数据问答"（README 路线图中"更强的语义检索"未完成项）；
- 演示亮点："老师上传一份提分策略文档后，AI 能结合班级数据给出针对性建议。"

#### 14. 个性化视角
- 同一份报告按角色（校长/教务/班主任/家长）切换叙事重点（前端已有报告受众切换，后端按受众裁剪摘要与建议即可）。

#### 15. AI 调用链路可视化（技术含量展示）
- 在系统设置/日志页展示一次 AI 问数的完整调用链路：模型名、token 消耗、各 Agent 耗时、调用次数；
- 面向技术型领导的"硬核 AI"证据，同时为成本治理做铺垫。

#### 16. 主动洞察推送
- 数据导入后自动触发分析：成绩波动、异常预警、知识点退化自动生成摘要并推送给对应角色；
- 把系统从"被动问答"升级为"主动智能"，这是 AI 感最顶级的体现。

## 四、演示脚本建议（下次演示直接用）

**总时长控制在 15 分钟，三段式：**

1. **开场（2 分钟）**：停留在"AI 能力橱窗"首页，逐张介绍 4 大能力卡——先让领导知道"AI 能做什么"。
2. **主演示（10 分钟）**：
   - 问题 1（快）：`扬州中学高三(10)班数学班级总览报告` —— 展示 NL2SQL + Agent 工作台动画 + 报告 AI 摘要；
   - 问题 2（复杂）：`全校各班横向多维对比` —— 展示多 Agent 协作、计划分步执行、图表联动；
   - 问题 3（亮点）：`临界生预警` —— 展示 AI 主动发现 + 预警 AI 说明 + 干预建议。
3. **收尾（3 分钟）**：打开"传统 BI vs AI"对比演示，强调效率差距；最后展示报告一键导出 PDF/Word、按角色切换受众。

**关键话术**：
- "整个过程没有任何人写 SQL，全部由 AI 自主完成。"
- "它不只是查数据，它会像分析师一样：先规划、再取数、再出图、最后写结论和建议。"
- "除了回答问题，它还会主动发现临界生、退步生，并给出干预建议。"

**彩蛋（可选）**：现场语音提问一次；现场上传一份成绩表后立刻生成报告。

## 六、验收标准（怎样算"AI 元素突出生动"）

- 打开系统 5 秒内，不需要讲解就能看到 AI 相关元素（品牌、能力卡、动效）；
- 一次提问中，用户/领导能"看到"AI 在规划、思考、写 SQL、出图、总结的全过程；
- 报告第一屏是"AI 的解读"，而不是冷冰冰的表格；
- 至少有 2 个"主动 AI"行为（预警说明、追问推荐、语音等）可在演示中一键触发；
- 全程无英文残留（如 `Thinking...`）、无无响应占位按钮。

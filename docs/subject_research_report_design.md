## 1. 背景与目标

### 1.1 背景

现有学校侧标准学情报告是 **9 类**（见 §2）。另已落地达线/局端 **7 类**（`LINE_REACH` + 6 个 bureau）。

教科院给部分学校出具的 Word 是另一套产品：**一校 × 一场 × 九科** 的「学科分析报告」。样本在：

```
E:\work\学情教育\
  1月八校分析报告\                 # 8 所学校各 1 份 Word
  3月调研测试八校学科分析报告\     # 同上（另有 PDF）
  5月市区八校分析报告\             # 同上
  八校分析报告三个月对比总结.md    # 他人整理的模板一致性说明
  5月高三分析报告\                 # 全市引领/支撑/发展/其他总体简版（非本需求）
```

三个月 Word **章节骨架相同**，差别只在数据与学校层级（引领 / 支撑 / 发展）决定的统计深度。

「八校」只是这批样本的学校集合，**不是产品类型**。用户实际会问「扬州中学 3 月学科教研分析报告」。

### 1.2 目标（第一期）

1. 新增报告类型 `SUBJECT_RESEARCH`，中文名 **学科教研分析报告**。
2. 粒度：**一所学校 × 一场考试**；未点名科目则九科全出，点名科目则只出该科。
3. 表格与名单用库内确定性计算；教学建议用规则短句，不复刻 Word 长文与试题立意。
4. **不得改变**现有 9 类 + 7 类的路由、工具、SQL、模板行为。

### 1.3 非目标（第一期不做）

- 一次出八校 / 批量 8 份
- 三个月对比总报告（`八校分析报告三个月对比总结.md` 只作口径参考）
- `5月高三分析报告` 全市引领/支撑/发展/其他总体简版（另一产品）
- 试题立意库、Word 级教研长文
- 改科目诊断 / 分层预警 / 局端尖子生名单 / 贡献分报告的对外函数语义
- 用「总分 − 卷1」反推卷2
- 接入 `privacy_mode` / 匿名学号 / 「刘**」半遮盖（隐私开关未修好前，本报告名单出明文姓名；修好后单点改 §4.4，不要提前接开关）

## 2. 与现有报告的关系

### 2.1 已有 9 类学校学情报告

| 枚举 | 中文名 | 典型问法 |
|---|---|---|
| `CLASS_OVERVIEW` | 班级总览报告 | 班级总览 |
| `GRADE_COMPARISON` | 班级横向对比报告 | 各班横向 |
| `SUBJECT_DIAGNOSIS` | 科目诊断报告 | 科目/学科诊断、小题、知识点 |
| `STUDENT_PROFILE` | 学生学情报告 | 个人画像 |
| `TREND_TRACKING` | 成绩趋势报告 | 走势、进退步 |
| `TIER_ALERT` | 分层预警报告 | 班级临界生 / 退步 / 偏科 |
| `GROUP_FEATURE` | 群体特征报告 | 按 X 群体 |
| `COMPREHENSIVE` | 综合分析报告 | 多次考试综合 |
| `DIAGNOSTIC_REPORT` | 结构化诊断报告 | 全市 / 区县诊断 |

### 2.2 已有 7 类达线 / 局端（不要和本报告抢）

`LINE_REACH`、`SUBJECT_AVG`、`ASSIGN_GRADE`、`RANK_BUCKET`、`CONTRIBUTION`、`COMBO_REACH`、`ELITE_ROSTER`。

本报告 **会复用** 尖子生（理前 100 / 文前 30）、贡献分、上场考试选取的 **计算口径**，但是：

- 产出是「某校某科章节里的子表」，不是单独的局端报告
- 实现时在新模块里 **调用现有纯函数或包一层**；不够用就新写，禁止改这些函数的对外行为

### 2.3 本报告 vs 科目诊断（最大混淆点）

| | 科目诊断 `SUBJECT_DIAGNOSIS` | 学科教研 `SUBJECT_RESEARCH` |
|---|---|---|
| 触发 | 科目诊断 / 学科诊断 / 普通「分析报告」 | 必须带「教研」或「教科院」 |
| 范围 | 可班可校；小题 + 知识点 + 能力层级 | **全校**；无班级切片 |
| 小题 | 尽量列出，侧重得分率 / 知识点 | **只列拖后腿题**（小题全市校际名次比本校总分名次低 N 名） |
| 名单 | 无理前 100 / 贡献分临界 | 按层级出尖子生、线下 10 分且该科低于贡献分的临界生 |
| 对比 | 班内 / 各班 | 全市校际排序 + **本层级全体均分** |

现有逻辑：带校名 +「分析报告」会走 `is_school_exam_report_query`，给科目诊断加分。因此本类型必须 **硬约束唯一候选**（与 `LINE_REACH` / bureau 相同），不能靠打分去抢。

## 3. 意图命中

### 3.1 正词（写进 `is_subject_research_report_query`）

命中任一即可（须同时能看出「要出报告」，「教研分析报告」已含「报告」）：

- `学科教研分析报告`
- `教研分析报告`（「教研」且「报告」，避免「教研组开会」）
- `教科院分析报告` / `教科院学科分析`

**不要用：** `八校分析报告`、`八校学科分析`、单独的 `学科分析`、`分析报告`、`小题`、`临界生`、`尖子生`、`贡献分`、`理前100`。

### 3.2 学校怎么定

粒度永远是 **一所学校**：

1. 问句能抽出校名 → 用该校（现有 `extract_school_target`，不要新写裸 `s_name LIKE '%校名%'`：`一中` 会打到高邮一中 / 邗江一中 / 市一中 / 江都一中）
2. 问句无校名 → 权限只有一所学校则用该校；局端 / 多校则提示「请指定学校」，不要默认全市、不要循环八校
3. 校名 → `tb_school`：`id` = `tb_score.school_id`（如 `GZ_19D9D68D`），`s_name` 如 `A01扬州中学`。对齐方式：抽取到的校名与 `s_name` **去掉校码前缀后的规范化校名**相等或为唯一后缀命中，禁止按「扬州」「一中」模糊 LIKE
4. 同码多校区：`A02扬大附中` / `A02扬大附中（淮海路）` / `A02扬大附中（广陵新城）` 是三个 `school_id`。问句是「扬大附中」且**未点校区** → 按校码 `A02` 合并全部记录（高三场次仅主校有分，合并不改 113.24；高二 6 月可能只在分校区有分，不合并会空）。问句已含具体校区（括号内地名）→ **只取该条 `school_id`，禁止再按校码合并**

### 3.3 路由接入（硬约束）

仿 `is_line_reach_report_query`：

1. `query_parse.is_subject_research_report_query(q)` 为真 → `_candidate_pool` **只返回** `[SUBJECT_RESEARCH]`
2. `_bureau_report_type` / `is_line_reach_report_query` / 全市诊断 / 个人画像 仍排在本探测器之前（那些问法本来就不会带「教研分析报告」）
3. 给 `SUBJECT_DIAGNOSIS` 增加负向词：`教研分析`、`教科院分析`（不要加「八校」）。**这是全文唯一一处修改现有行为的点**（兜底打分表），硬约束命中时其实用不到，属双保险；必须同步在 §6.2 备案并保证旧路由用例不受影响
4. `_TIE_BREAK[SUBJECT_RESEARCH]` 高于科目诊断即可；硬约束命中后打分不再参与
5. `is_school_exam_report_query` **不要**为本类型加分（保持原样，避免「分析报告」误伤）

### 3.4 路由验收问句

| 问句 | 期望 |
|---|---|
| 扬州中学 3 月学科教研分析报告 | `SUBJECT_RESEARCH`，九科 |
| 扬州中学数学教研分析报告 | `SUBJECT_RESEARCH`，仅数学 |
| 给我出一份学科教研分析报告 | 类型命中；学校走权限或追问 |
| 扬州中学 3 月数学科目诊断 / 学科诊断 | `SUBJECT_DIAGNOSIS`（不变） |
| 扬州中学 3 月数学分析报告（无教研/教科院） | **维持现状** → 科目诊断 |
| 高三(5)班临界生预警 | `TIER_ALERT` |
| 全市理前 100 | `ELITE_ROSTER` |
| 贡献分分析 | `CONTRIBUTION` |
| 八校分析报告 | **不命中**本类型 |

实现后必须给上表加 `tests/agent/test_report_intent_routing.py` 用例；旧问法路由快照不得变。

## 4. 报告结构（对齐 Word）

每校一份，九科（或指定一科）重复下列章节。层级只影响 **出哪些章 / 用哪条线 / 小题门槛**，不改表头。

### 4.1 章节 × 层级

| 章节 | 引领校 | 支撑校 | 发展校 | 其他校 |
|---|---|---|---|---|
| 一、整体情况 | 有 | 有 | 有 | 有（同发展校） |
| 二、小题分（仅拖后腿） | 名次低 **2** 名及以上 | 低 **3** 名 | 低 **3** 名 | 低 **3** 名 |
| 三、尖子生 | **有**（理前 100 / 文前 30 中的本校生） | 无 | 无 | 无 |
| 四、临界生 | **211 线 + 特招线** | **特招线 + 本科线** | **仅本科线** | **仅本科线** |
| 五、教学建议 | 规则短句 | 同左 | 同左 | 同左 |

- 特招线 = 特控线（现有 `canon_line_name` 已如此）。
- 临界生定义（Word 注）：该线 **下 10 分以内**，且该科成绩 **低于学科贡献分**；物理 / 历史方向分表。
- 差值定义（Word 注）：学校均分 − **本层级全体均分**；排序 = 本校在 **扬州市所有已入库学校** 中的名次，不是八校内排名。
- 支撑 / 发展 / 其他：结论句额外写「比本层级第 1 名低 X 分」。

### 4.2 整体情况表（12 列语义）

表头与 Word 一致：学校 | 本次考试（均分、排序、差值、1 卷、排序、2 卷、排序）| 上次考试（均分、排序、差值）| 排序变化。

两行：本校 + 本层级全体。

表脚注（模板必含）：「卷1/卷2 由逐题明细按题型归集，均分与卷1+卷2 允许存在微小出入」（Word 英语行 79.69+38.84=118.53 ≠ 总分 118.78，Word 本身即如此，不加脚注会被当成数据错误）。

### 4.3 小题分表

列：题号、均分、排序、最高分、最低分、与总分排序的差值。

只保留 **拖后腿** 的题：`小题全市校际名次 − 本校总分全市校际名次 >= N`（名次 1 为最好；「拖后腿」= 小题名次数字比总分名次**大** N 及以上）。

⚠️ 符号方向易错：差值若按 Word 的「与总分排序的差值」列定义（`总分名次 − 小题名次`，拖后腿题为负），过滤条件是 `差值 <= -N`；两种写法等价，但不要写成 `小题名次 − 总分名次 <= -N`（那是「比总分还靠前 N 名」，方向相反）。

**试题立意：第一期不输出**（库中无此字段）。不要用 LLM 冒充教科院立意。

### 4.4 尖子生表（仅引领校）

- 物理方向：全市 `zf6m` 前 100（含并列口径与现有 `build_elite_roster` 一致），筛本校
- 历史方向：前 30
- 语数英物：原始分 + 学科排名
- 化生政地：原始分 + 等级分 + 等级 + 学科排名
- 学生标识（第一期）：**明文姓名**（`tb_score_overview.xm`，按 `anon_stu_id` 对齐）。**不调用** `is_anonymize_display_enabled`，不要复用 `build_elite_roster` 里剥姓名的分支（包一层自己出 `xm`）。系统目前也没有「刘**」半遮盖。隐私开关修好后：改为走 `privacy_mode`（开=匿名学号，关=姓名），只改本报告名单列
- 尖子生基于 `zf6m` 总分：市报生科目列多为 NULL 自动排除，但总分列可能有值，计算时**显式排除 `xsxz='市报生'` 与 `tb_school.type='市报'`**

### 4.5 临界生表

列：姓名（第一期明文 `xm`，同 §4.4）、总分、学科分（Word 为双列并排，HTML 可单表）。无名单时仍输出空表 + 口径注。基于总分的筛选同样显式排除市报生（同 §4.4）。

### 4.6 「其他校」用哪套模板

**不要**用 `5月高三分析报告/…发展校其他校.docx`。那是全市总体简版（达线率 / 临界 / 总分 / 学科均分），不是单校九科教研稿。

单校教研：

- **章节深度** = 发展校（无尖子生、仅本科线、小题低 3 名）
- **对比基准** = `tb_school.type='其他校'` 的全体均分（`tb_score` 口径），**禁止并进发展校**（3 月语文发展校约 101.88、其他校约 96.43，混用差值会偏约 5 分）

`type` 空或无法识别：按其他校章节出，并注明「未分层，对比基准用其他校」。

> 「其他校」出发展校深度章节是本设计的**新增决策**（Word 八校样本只有引领/支撑/发展三档，其他校是库内真实存在的第四档）。第一期按上表做即可；若产品确认其他校不出本报告，再改成提示不支持，不要回头改引领/支撑/发展。

**市报**：`tb_school.type='市报'` 不作为教研层级，也不进入引领/支撑/发展/其他的均分分母；名单侧再排除 `xsxz='市报生'`。不要用 `overview.xxlb` 判断市报（3 月 overview 会把市报生标进引领/支撑/发展，层级均分会对不齐 Word）。

## 5. 数据能否拿到（已用 edu 库对过 Word）

数据源：教育业务 PG（`tb_score` / `tb_score_detail` / `tb_exam` / `tb_exam_question` / `tb_score_overview` / `tb_exam_batch` / `tb_fraction_bar`）。平台库不参与计算。

批次与 Word 对应：`2026届高三1月期末` / `2026届高三3月` / `2026届高三5月模拟`（另有 11 月期中、高二 6 月期末，本报告同样可用，不限制死三个月）。

3 月语文全市 **45 所学校**。层级以 `tb_school.type` 为准（引领 / 支撑 / 发展 / 其他 / 市报）；`overview.xxlb` 与 type 不一致处几乎全是市报生，**分档禁止用 xxlb**。

### 5.1 字段映射

⚠️ **均分 / 排序 / 层级均分一律用 `tb_score.score`；层级归属一律用 `tb_school.type`。** `overview` 科目列是另一份导入拷贝（3 月语文：红桥 `tb_score` 104.46 = Word，`overview.yw` 103.74，差 0.72；新华 107.86 vs 107.60），禁止当均分源。`overview` 只用于：`zf6m`（尖子生/临界生总分）、`xkkm`（物理/历史方向）、`xsxz`（排除市报生）、`xm`（第一期姓名）、`anon_stu_id`（对齐）。**不要用 `overview.xxlb` 分档。**

| 报告项 | 来源 | 第一期 |
|---|---|---|
| 学校科目均分、全市排序 | **只用 `tb_score.score`** 按校 AVG 再 RANK（禁用 overview 科目列） | 做 |
| 层级均分 / 差值 | `tb_score.score` 经 `tb_school.type` 分档（引领/支撑/发展/其他），同档全体学生 AVG；排除 `type='市报'` | 做 |
| 上场考试 | `tb_exam_batch.exam_time` 取上一场（复用 `pick_previous_exam` 思路） | 做 |
| 卷1 / 卷2 | 明细 × 题型分桶（§5.2），**不是** overview 的 `sxkg/ywzw/yyzw` | 做 |
| 拖后腿小题 | `tb_score_detail` 校均 + 各校该题均分排名 vs 本校总分校际名次 | 做；报告脚注写清「排名范围=本场已入库学校」 |
| 试题立意 | 无 | 不做 |
| 尖子生 | 复用 elite 口径，滤本校；排除市报生（§4.4） | 做 |
| 临界生 | `tb_fraction_bar` + 现有贡献分；线下 10 分且该科 &lt; 贡献分；排除市报生 | 做 |
| 教学建议 | 规则短句（均分相对层级高低、拖后腿题号、临界人数） | 做短句 |
| 学生姓名 | 第一期明文 `overview.xm`（§4.4）；不接隐私开关 | 做 |

标识对齐（已连库验证）：`tb_school.id` 形如 `GZ_19D9D68D` = `tb_score.school_id`；`tb_school.s_name` 形如 `A01扬州中学`（与 `overview.xx` 同格式）；**`tb_school.type` 直接就是层级**（引领 9 / 支撑 15 / 发展 12 / 其他 6 / 市报 7 所），层级归属不需要经 overview join。卷/小题/均分全走 `tb_score.school_id`。

### 5.2 卷1 / 卷2 口径（已与 Word 对上）

库无卷别列。算法：

1. 按 `question_id` 把 `tb_score_detail.score` 分到卷1 或卷2
2. **每生**对卷1 / 卷2 分别求和
3. **按校（或按层级）**对每生卷分求均，保留 2 位小数

已复核：

| 项 | Word | 库 |
|---|---|---|
| 3 月语文 · 扬州中学 总 / 卷1 / 卷2 | 115.92 / 24.59 / 91.34 | 115.92 / 24.59 / 91.34 |
| 3 月语文 · 引领校 卷1 / 卷2 | 23.55 / 89.50 | 23.55 / 89.50 |
| 3 月英语 · 扬州中学 卷1 / 卷2 | 79.69 / 38.84 | 79.69 / 38.84 |

**均分列与卷列可以不是同一数据源（必须写进实现注释）：**

- 「均分 / 全市排序」只用 `tb_score`（§5.1）。英语扬州中学总分均分 **118.78**，明细卷1+卷2 **118.52**；Word 学校行均分用总分、卷用明细。
- 「卷1 / 卷2」只用明细。禁止 `卷2 = 总分 − 卷1`。
- 表内允许 **均分 ≠ 卷1+卷2**。
- 层级「均分」列与学校「均分」列用同一科目源（`tb_score`）；不要用明细加总去替代英语那种总分列。`overview.xxlb='引领校'` 会掺上市报生（11 校 / 112.99 分）；`tb_school.type='引领校'` + `tb_score` 为 7 校 / **113.05**，卷1/卷2 为 **23.55 / 89.50**，与 Word 层级行一致。

题型映射做成 **配置**（tuple / frozenset），匹配 **先卷1 后卷2**：

1. 卷1：`单选题` / `多选题` / 以它们为前缀；`听力`、`阅读理解`、`完形填空`、`七选五`（及前缀）
2. 其余进卷2：`解答题*`、`简答题*`、`写作`、`书面表达*`、`翻译*`、`默写*`、`填空题`、`语法填空`、`修改题`、`改写题` 等

顺序不能反：「完形填空」不得被「填空」分进卷2；「语法填空」不得进卷1。

高三 1/3/5 月九科题型几乎只有「单选题 / 多选题 / 解答题」，与 Word 对齐足够。细类出现在高二 6 月期末，配置仍要兼容，但不要按细类名去猜高三卷结构。5 个批次 × 9 科 `question_type` 实测无空值。

### 5.3 上线前数据冒烟（实现后跑一次，不必写进 CI 连真实库）

用 3 月 + 扬州中学（引领）/ 新华中学（支撑）/ 红桥高中（发展），**全部按 `tb_score` 口径核对**：

- 语文校均 = Word 115.92 / 107.86 / 104.46（已实测 `tb_score` 口径可精确复现；`overview` 口径为 115.92 / 107.60 / 103.74，对不上 overview 是**预期行为**，说明用错源）

- 卷1/卷2 语文扬州中学 = 24.59 / 91.34；英语 = 79.69 / 38.84
- 扬大附中语文 = 113.24（校码 A02 合并口径，验证多校区合并规则）

## 8. 测试计划

1. **路由**：§3.4 全表；旧用例 `test_report_intent_routing.py` 全绿。
2. **题型分桶**：单测配置——`完形填空`→卷1，`语法填空`/`填空题`→卷2，`单选题（文言文）`→卷1，`解答题（导数）`→卷2；空题型记 other 不丢行。
3. **卷均分**：fixture 几名学生小题分，断言校均卷1/卷2 与「禁止用总分减」；允许均分 ≠ 卷1+卷2。
4. **拖后腿方向断言**（防 §4.3 符号回归）：总分全市第 1、某小题第 3、N=2 → 该题**入选**；小题第 1、总分第 3 → **不入选**。数据源断言：均分/层级计算只读 `tb_score`（可对 overview 科目列取不同 fixture 值，断言输出不变）。
5. **层级章节**：同一套 data builder，按 `tb_school.type` 分别引领/支撑/发展/其他，断言尖子生章显隐、临界线集合、小题 N=2 或 3；其他校基准 key 为其他校不是发展校。

7. **名单**：第一期尖子生/临界生表含明文姓名字段；断言**未**调用 `is_anonymize_display_enabled`（隐私开关修好后再改此条）。
